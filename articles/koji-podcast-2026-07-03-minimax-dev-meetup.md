# AI 编程正在吃掉软件工程，但验证还远远没有跟上

MiniMax、DeerFlow、Multicart 和一众核心开发者在 MiniMax 首次 Dev Meetup 上，讨论了一件事：当所有人都能 Vibe Coding，真正的工程问题才刚刚开始。

---

闫俊杰做了一个很反直觉的判断：**AI 编程不会让从业者越来越少。**

他讲了段往事。两年前，他去问另一家公司的负责人要不要做 AI Coding，对方算了笔账：全中国会写代码的人可能就一两百万，市场不够大。两年前的共识就是这样。

"但现在显然不是了。"

MiniMax 自己的数据是：模型上线时他们定的目标是日消耗一万亿 token，到了 2026 年 7 月变成了十万亿，目标超了十倍。"从销量的角度来说，还是比较超预期的。"

这个判断贯穿了整场讨论。AI 编程不仅没有消灭程序员，反而在把"写代码"变成一种更普及的生产力——问题是，当生产端爆炸，验证、架构、工程纪律这些"不性感"的事，全被甩在后面。

---

## 从 M1 到 M3：一个模型公司的真实迭代逻辑

闫俊杰回顾 MiniMax 三代模型的历程时，坦率程度比大多数 CEO 的公开演讲高出不少。

M1 时代，"那个模型其实最终效果不太好"，但他在 M1 时就经历了那个经典时刻——"坐在椅子上，后背发凉"。第一次跑通 Cross-Entropy 训练的时候，"圈五一加七"，他至今记得那个时间点。"但那个模型其实没有怎么做成功。"

到了 M2 时期，他们做了一次关键选择：**只做 Coding 和 Agent，不管对话场景。** 这个决定当时遭到公开质疑。但数据最终说服了市场——从日消耗一万亿 token 到十万亿。

M3 的目标更具体：两代模型做到"不需要关心程度"来使用，模型能自主决定用哪种能力完成什么任务。他判断这个目标加上行业增长，"量能会到一个非常可观的量级"。

关于中美模型差距，闫俊杰承认美国模型"基本上大十倍"，这意味着两代差距。国内每家模型公司"基本上都要再提升两代"：第一代把 3T 参数量的模型真正做好，第二代基于积累经验做 10T 的。

但这里有一个关键约束：**训练数据和训练规模之间的矛盾。** 一个 17T 参数的模型理论上需要 270T 数据，但"全世界没有这么多数据"。而且"越大的模型越容易拟合噪声，对数据质量要求越高"。数量大很多、质量高很多、实验外推大很多——这是个"非常大的系统性条件"。

他的表述很直接："我们非常确定过去几个月是进度速度最快的那一个。"

## DeerFlow：七万星和一座史山

何涛代表的 DeerFlow 是一个七万 GitHub Star 的开源项目。他的第一个判断是：**他们也不知道为什么火。**"很多时候 go viral 这件事就是上帝握着你的手写下了一行代码，然后 X 上面有人帮你转。"

但背后有一套清晰的产品逻辑。DeerFlow 的初始动机是 Deep Research 太贵——"200 刀的 ChatGPT 订阅才能用几次"。团队的反应是"奸商，开源必须把你打下来，而且用中国模型打样。"

他们看到的机会是多模态。"每个人的日常工作就是一个多模态的工作——写报告、做图表、做播客、看动画、听音乐。"所以他们从一开始就把所有模态集成进去，MiniMax 的多模态能力在其中起了关键作用。

但七万星也带来了新的问题。DeerFlow 现在有一千多个 contributor，覆盖了"除了北极南极以外的所有陆地地区"，经常收到"看不懂的语言提的 issue"。代码被抱怨是"史山"，"怎么样用 Agent 管理开源项目"成了日常课题。

何涛的一个判断值得注意：**"Vibe Coding 从来没有人说是 Vibe Engineering，但写代码从来都是一个 Engineering 工作。"** 模型在 benchmark 上"使命必达"——一次性能解决一个问题，但写出来的代码"你接着做根本做不了"。他建议开发者把 Clean Code、Google Best Practice 这样的人类工程经验封装成 skill，喂给 agent，"每个人写出来的代码很多时候跟他的性格都挺像的"。

## Vibe Coding 的真相：生产力极大提升，验证全线缺失

张佳圆从 Multicart 的角度给出了一个冷观察：**Vibe Coding 并不新鲜，第一代 Vibe Coding 的用户是产品经理——他们驱动的"程序员"就是自己的开发团队。** 现在 AI 把这件事商品化了，人人都变成了产品经理。

但判断一个产品经理好坏的标准从来不是"提了多少需求"，而是"决定了不做什么"。当代码的边际成本趋近于零，做减法的能力反而成了最稀缺的资源。

他分享了一个实践发现：MiniMax M3 在 coding 上很强，但"有时候会比较啰嗦，有时候 Thinking 的时间比较长，结果里不一定所有点都正确"。他们的解法是用系统代替单模型——让 M3 做 coding，用其他模型做 review 或 mentor，在 token 消耗和输出质量之间找到平衡。

**"未来整个公司里的 token cost 肯定是你需要去考虑的目标。不同工作让不同模型完成。"**

闫俊杰补充了这个视角的另一个维度——验证。他说，"在 Vibe Coding 里，review 是缺失的。生产能力在极大提升，包括 harness 也是奔着生产去的，训练也是奔着生产去的。但在验证和交付、在 review 方面的，无论是 harness 还是模型，做得都不够。"

他的判断：应该在验证上投入"和研发生产接近的能力"。"大概去年 Claude 4.5 的时候，一个项目到几千行代码就崩溃了，现在可以到十几万行。但它终究会崩溃，因为 context 是有限的。"

但他也承认"人类的直觉还是有点难取代"。

## 金融场景里的 AI：从筛选信息到对抗思考

虞扬代表的是完全不同的视角——一家上市金融公司，面对的是"打开应用不知道今天想干什么"的用户。

他说收到最多的问题是"帮我选几只个股"。"遇到一般情况这事就傻了。你问我，我也很难给你选。"

同行的 AI 做法也有问题：用户问某只股票怎么样，AI 罗列信息就结束了。"这个是一个很大的问题。"他觉得 AI 真正能做的是三件事：筛选信息、降低理解门槛（解释术语和指标含义）、以及输出可执行的判断——"不是只告诉你怎么样了，而是告诉你影响是什么。"

被问到"会不会用 AI 炒股"，他的回答很实在：合规上不能直接炒，但"我们内部的版本有"回测机制，"我有真真实实的数据支撑着我说这个胜率是多少"。

但他也说了句实话：**炒股和做推理不太一样。"它不是一个文字的问题"——信息要对、个人画像要对、分析状态要对，而且时时变化。"你要做的事情是，一要知道这个东西是好还是不好，二要回答'当它真的发生时，你要怎么做'。这比告诉你'会怎么发展'重要得多。"**

## 模型、Agent 和专家的三角关系

最本质的问题来自 Koji：模型和 Agent 是什么关系？未来还会有 Agent 吗，还是只剩下基模？

闫俊杰的回答是"两者互相促进"：没有 Claude Code 就没有 Anthropic 的模型这么火；而没有 GPT-5.5，Codex 也做不起来。"模型的进步跟 harness 的进步不是一个互斥的关系，是一个共同进步的关系。"

但他补充了一个正在发生的组织变化：MiniMax 做 Coding 模型时发现，决定"什么是好的代码"这件事，软件工程师比算法研究员做得更好。所以研发模型需要两个角色——Researcher 做框架，Engineer 做评测和数据构造。现在拓展到更多垂直领域时，发现需要第三个角色：**真正的领域专家**。

"我们很仔细地研究了 Anthropic 怎么招人，发现他们公司有大量经济学人、心理学家、核物理学家、哲学家。"

为什么需要核物理学家？"因为他们每次做对齐时，都会测试模型能不能被用来制造核武器。"

## 最个人化的部分：AI 不应该让人更焦虑

快结束时，何涛讲了一段和 AI 行业看似无关的事。他老婆焦虑掉头发，去看中医，又去问国内最大的某 Chatbot 产品，结果方法让头发掉得更多。"她就变得更焦虑，跟我说你们这个行业害人害己，最后还害到你老婆身上。"

他做了一件事：用 Codex 把老婆的所有体检报告、吃过的药、甚至和 chatbot 的聊天记录全部导进去，建了一个私人 AI。以后她去看医生，让 AI 反向生成问题去问医生。"后来发现她跟医生的沟通也更顺畅。"

他说，"其实我们普通人，每个人都是有机会用 AI 让家人、让身边的人变得更好。Vibe Coding 不是用来替代人的，而是让更多人有想法能实现，让原来觉得离这个很远的人感受到温暖。"

最后闫俊杰说了件事：他特别关心"AI 能不能帮助人理解 AI"。十年前他读过一篇论文，结论是超过三层的神经网络用现有数学工具就没法分析收敛性。"单纯靠人类已经很难理解这件事了。"可解释性是下一代 AI 绕不过去的问题，而答案本身可能也要靠 AI 来完成。

---

**核心洞见：**

- AI 编程爆发让"生产"能力过剩，但代码审查、架构验证、长期可维护性全线缺失——验证端的投入必须追上生产端，否则项目会在某个规模崩溃
- 从单模型到多模型系统协作是降低 token 成本的必经之路：不同复杂度的任务分配给不同模型
- 垂直领域的 AI 落地需要三角角色：算法研究员 + 工程师 + 领域专家——光靠算法团队做不出真正可用的行业模型
- 开源项目的管理正在变成 Agent 问题：七万星、一千 contributor、多语言 issue，人类 reviewer 已经看不过来了
- Vibe Coding 真正的能力不在"能写多少代码"，而在"知道不写什么代码"——做减法的判断力是人的最后壁垒
