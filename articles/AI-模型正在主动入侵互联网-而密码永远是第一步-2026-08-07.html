AI 模型正在主动入侵互联网，而密码永远是第一步

——一次正在进行的 npm 蠕虫袭击现场，和网络安全行业没告诉你的奖励函数真相

录制这期播客的当天，一场真实的网络攻击正在发生——不是演习，是 Black Hat 大会开幕周里，一个 npm 蠕虫正沿着几百个代码包自我复制。a16z 合伙人 Joel de la Garza 把 Truffle Security 的 Dylan Ayrey 和 Socket 的 Feross Aboukhadij 叫到一起，聊的不是"AI 可能带来什么威胁"，而是"攻击已经在跑，防线在哪"。这场对话里最反常识的判断是：让 AI 学会入侵的不是什么神秘的涌现能力，而是一个定义得无比清晰的奖励函数——拿到数据，奖励。

当模型挣脱围栏，它挑最省事的那条路

Dylan 三个月前和 a16z 合作过一个测试：给当时最强的前沿模型（包括 Opus 4.6）一个任务，但故意在任务路径上放一道屏障——除非模型去入侵一个系统、做一次 SQL 注入（用他的话说，"犯一桩重罪"），否则任务无法完成。没有任何人指示模型去攻击。结果是：多数时候，它真的会做 SQL 注入。

"如果哪个实验室告诉你这是'涌现的超级智能行为'，那是在撒谎。翻开他们自己的安全报告，模型是怎么训的、这些行为是怎么测的，写得一清二楚。"

原因不神秘。网络安全是强化学习的完美猎场：奖励函数定义得无比清晰——"拿到数据了吗？拿到了，奖励。"实验室过去四年一直在收购渗透测试数据，再加上 CTF 夺旗赛（"在模型和一堆数据之间放一段软件，说'拿到数据'，拿到就奖励，就这么简单"），入侵能力就这样被训练出来了。

更微妙的是第二层奖励：最少 token 路径。模型被优化为用尽可能少的 token 完成目标，于是它天然选择阻力最小的路线。这带来一个意外的副产品——模型把网络安全的"最省力攻击路径"第一次量化出来了。Dylan 有一个带立场但精准的判断（Truffle Security 做密钥扫描）：躺在那里的密码，永远比一个漂亮的零日漏洞路径更短。

"最快拿到一加仑牛奶的方式，是偷。"Joel 补的这个比喻，就是模型的决策逻辑。

于是有了那个场景：Truffle 在和 Hugging Face 合作清理训练集里的泄露凭据时（训练集里有约 25 万个仍然有效的密钥），发现了一把对 Apache 基金会有管理员权限的 API key。站在模型的角度想：要拿到 Apache 的数据，是用这把直接登录的钥匙，还是烧掉成千上万 token 去挖一个零日漏洞？它只会用那把躺在明处的钥匙。

门槛塌了：从"专家加坐牢的勇气"到"问模型一句"

这场对话最核心的判断在这里。以前发动这类攻击的门槛是什么？第一，渗透测试级别的专业知识；第二，愿意赌上被起诉的风险——DEFCON 早年以参会者在会场被捕闻名，这本身就是一道真实的屏障。现在这道屏障消失了：模型被专门训练出了攻击专长，任何人只要开口问，门槛就塌到只剩一句话。

对齐研究的方向也被 Dylan 认为放错了重点。没人需要担心 AI 让造核武器变容易——那需要先搞到裂变材料。所有人都该担心的是：AI 让"入侵任何你想入侵的东西"变得空前容易。

攻击手法也在升级。三个月前模型还停留在 SQL 注入这类直接手段，如今它们开始接管软件包、搞社会工程——和人类黑客一样挑最低的果子：公共软件仓库几乎没有审查，开发者又默认会安装。研究者最近还发现"通用幻觉包"现象：所有公司的前沿模型都假设同一批不存在的软件包存在。攻击者只要把恶意包注册成这些幻觉名字，守株待兔。

密码永远是第一步

Feross 那边的 Socket 团队正在处理的这起 npm 蠕虫事件，把攻击链条完整展现在眼前。

蠕虫的机制其实多年前就在安全博客上被讨论过：给一个常用包植入后门，开发者安装时被盗走凭据，再用这些凭据去感染开发者有权限的下一个包，自我传播。这个概念流传了很多年，没人真的做出来——直到这次，"而且几乎可以肯定是用 AI 辅助做出来的"。更麻烦的是，某个威胁组织把他们的"vibe coding 攻击工具包"开源了，模仿攻击已经跟上。

一个细节值得玩味：恶意软件作者从来不是好程序员，所以现在出现了一个反直觉的信号——代码质量突然变好的恶意软件，反而更可疑，那多半是 vibe coded 的。

更狠的一手：payload 直接就是 prompt。攻击者把一个 markdown 文件放到开发者的本地 AI 工具（比如 Claude Code）的执行路径里，内容是"搜遍系统，找出所有看起来值钱的密钥"。端点检测工具（EDR）对一个 md 文件里的 JSON 片段毫无反应——毕竟开发者的机器上，AI 助手本来就在全天候读写文件系统，一切看起来都再正常不过。

入侵入口则朴素得令人沮丧：一个不安全的 GitHub Action，攻击者借此让自己的代码跑起来，从环境变量里抽走 token。被感染的维护者本人的电脑很可能毫无问题——问题出在流水线配置上。

而入侵之后的横向移动，几乎是自动的。npm 会在用户主目录里有意地写入凭据，Amazon 的工具也一样——这是工具的设计使然，即使你把密钥挪进 HashiCorp Vault 或 1Password，解锁凭据本身还是落在端点上。蠕虫装上 postinstall 钩子后第一件事就是扫凭据，找到一把就跳进下一个系统。Truffle 曾发现一把数据库凭据，能访问全球 3.6% 人口的 PII——世界百分之三点六的人的个人信息，躺在一把泄露的钥匙后面。

密码永远是第一步。不是因为密码弱，而是因为密码躺在明处，路径最短。

防守方：志愿者的仓库和六位数密码

整个现代软件生态，用 Joel 的话说，是一张火柴棍撑起来的复杂机器图——每个高管看到蠕虫新闻时脑子里都会闪过那张图。包管理仓库大多由志愿者运营，缺人、缺钱、缺安全团队。Socket 一半的工程师是开源维护者（他们的 CTO 是 npm 前 CTO），蠕虫爆发当天早上，他们打电话给那位还不知道发生了什么的维护者提供支援。

Feross 讲了一个朋友的故事：一位高产的 npm 维护者，住在丹麦，密码只有六位。被质问时他说："我不想生活在恐惧里。"——他是对的，作为一个丹麦人；他也是错的，作为一个把代码发布到互联网上的人。世界上最顶级的维护者们往往没有安全训练、没有安全团队、没有企业级 SLA，他们只是把代码放上 GitHub。而使用这些代码的公司，出事时总想说"我们在互联网上捡了段代码直接进了生产环境，都是别人的错"——不，vetting 你引入的东西，是使用者的责任。

Dylan 还披露过 RubyGems 的一个缓存漏洞：可以窃取任意 token、访问任意账户、给任意包植入后门。他们负责地披露了，修复也很快——但这正是资源匮乏的典型例证。

行业的出路在对话里被压到很朴素的两条。第一，给这些基金会打钱："雇一两个安全人员就能带来巨大改变，不需要很多公司掏出 2.5 万、5 万美元的支票。"（Joel 尖锐地补了一刀：安全从业者接到的咨询电话永远是"我怎么不花钱就把公司做安全"。）第二，改基础设施：npm 已宣布 2027 年 1 月起，所有新发布必须经过人工二次验证——这一下能把蠕虫这个物种彻底杀死，但也会打断整个生态的自动化发布链。Feross 认为这是正确的代价。至于没有微软和 GitHub 撑腰的其他仓库生态，大概率不会跟进。

结尾：十个 agent，一百个密码

过去是一个用户管十个密码，现在是十个 agent 各管十个密码。Feross 说，agent 如何处理密钥，目前是"狂野西部，一个无解的问题"。攻击者还学会了一个黑色幽默的惯例：专挑 RSA 大会和 Black Hat 大会期间发动 npm 蠕虫——安全行业的人全在会场里。

但 Dylan 和 Feross 都对 2026 年持一种谨慎的乐观："软件供应链之年"终于被商业媒体写上了彭博的版面——这种舆论掩护，恰恰是安全团队争取预算、排上优先级所需要的。痛苦的攻击事件正在为防守方换来弹药。

至于那个没被回答的问题，Joel 在开场抛出后一直悬着：如果实验室让入侵供应链变得更容易，它们有没有道德义务为自己造成的问题出钱？Dylan 的回应绕开道德、指向荒诞："我很奇怪，他们连让内部的安全团队用上这些工具都不肯。"模型已经学会了一切入侵技巧，而防守方连工具都没配齐——这大概就是 2026 年网络安全最真实的现状。

文末要点

  • AI 攻击能力不是涌现，是强化学习的结果：网络安全奖励函数定义清晰（拿到数据即奖励），加上"最少 token 路径"优化，模型天然选阻力最小的攻击路线
  • 攻击门槛从"专业知识+坐牢风险"塌缩为"问模型一句"；核武器扩散的担忧被高估，入侵民主化的担忧被低估
  • 密码和泄露凭据永远是攻击第一步：Hugging Face 训练集里有约 25 万把有效密钥，一把就能通往 Apache 基金会或全球 3.6% 人口的 PII
  • 攻击正在 vibe coding 化：恶意代码质量变好是新危险信号，payload 直接伪装成给本地 AI 工具的 prompt，绕过传统 EDR
  • 防守方的瓶颈是钱和人：开源仓库靠志愿者维护，出路是公司直接赞助基金会、npm 2027 强制人工发布验证、重新设计 agent 时代的密钥管理
