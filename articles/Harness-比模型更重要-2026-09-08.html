Harness 比模型更重要

YC 的一场活动上，同一份模型权重被用出了 30 分到 95 分的差距

Reddit 上有条评论说得毫不客气：「我不觉得这种 Prompt 工程配得上顶级机器学习会议。」另一条更绝：「上下文工程根本就不是个科研课题。」

而在一场名为 Harness Club 的 YC 活动上，开场演讲者用一晚上试图证明的是相反的事情。

Harness——模型外面那层决定它可以调用什么工具、拥有多少记忆、能连续跑多久的脚手架代码——长期以来被视为「不入流」。但它交出的一组数字很难被轻蔑：从 Harness 1 到 Harness 2 的迭代，实打实带来 18% 的提升；在最难的 Arc AGI 私有测试集上，一批模型的最好成绩曾经只有 30%，而配上合适的 harness，同一个任务做到了 95%，英伟达的配置甚至做到 100%。

「过去这六个月，全都是关于具备自我改进能力的 harness。」如果说此前几年行业的主线是训练更强的模型，那么现在最前沿的一条伏线是：把同一个模型用得更好——而这件事的开发空间，远比大多数人以为的更大。

六年时间，从 while 循环到子 agent 军团

演讲者花了五分钟，把 harness 的历史从 2019 年拉到现在。这段历史很少被讲起，但它解释了今天所有 agent 产品的形状。

2019 年 2 月的 GPT-2，harness 的本质是一个 while not end of sequence 循环，配上 top-p 采样和一个运行环境，就这样——没有工具调用、没有技能、什么都没有。一个典型的例子：系统提示词写着「你是一个数学老师」，然后给一道应用题（Susy 有 5 美元，花掉 3 美元，还剩多少），直接让它输出答案，对错就是 1 分和 0 分。

接下来的六年，所有人都在做同一件事：往这个循环里塞更多东西。

把几个例子放回上下文，是少样本学习（2020 年 7 月）；让模型把计算摊薄到更多 token 上、先推导再给答案，是思维链；给模型一个能调用的 Python 对象、让它别在上下文里硬算「5 减 3」，是工具调用；让模型能对自己那块「记忆」增删改查，是后来最酷的工具之一；而 Voyager 那篇论文提出：把学会的技能蒸馏回系统提示词，模型就能永远掌握这项能力——今天所有 agent 产品里的「技能」（skills），概念就源于此。再往后是 Intercode（代码即工具）、ReAct、Self-Refine、Reflection（多个角色互相审阅、自我改进）、能派生出常驻子 agent 的多智能体结构，直到 RLM 暴露递归调用接口：主控 agent 统领一切，叶子上随时派生出新的 LM agent。

所有这一切，被统称为「静态 harness」：你定义一套 agent 规范，写一段系统提示词，规定最多跑几轮、允许调用多少次工具，指定工具列表、技能列表、子 agent 列表，然后把它放进一个循环。

这个形态完成后，立刻显出威力。演讲者举了自己的例子：他把 Karpathy 三月份发布的自动科研项目 fork 过来，本意只是做个小界面看看运行情况，结果阴差阳错手搓出了一个完整的 harness。他给系统一个真实目标——「扩散 LLM 跑不过自回归 LLM，但如果把扩散 LLM 切片分片成多个实例，因为扩散模型单卡算力强度更高，模型融合可能拿到更好效果」——然后 agent 们自己开工了：一个负责梳理范围的 agent 去查论文、查 GitHub；一个 PI agent 接棒；一个研究员 agent 推进具体工作；顾问委员会给反馈；甚至还有一个每小时来催一次进度的监督 agent；最后写作 agent 停下来，把思路定稿、写消融实验、写论文。到今天，他的用法是：「把八个想法丢给八个 H200 节点，每个节点带八张 H100，自己去跑。我过来看看，他们就直接交论文给我。」他读了那些论文——「写得很不错」。三月和四月还不太行，五月就变好了。

让 harness 自己进化

静态 harness 时代积累的进展，被一张经典图表概括：横轴是模型发布时间，纵轴是 agent 能持续运行的时间长度。这条曲线上的很多进展，直接来自 harness 的改进。

而最近的六个月，主题变了——让 harness 本身去学习。

一条路线是只优化系统提示词：DSPy 用遗传编程的思路，拿一个训练集和少量样本，不断寻找候选提示词、合并、评估，「相当于赋予了对系统提示词本身的增删改查能力」。

另一条路线走得更远：不只改提示词，连 harness 的代码一起改。你有一份由无数个「harness + system prompt」组合构成的档案，采样跑起来，用适应度函数评估，再把结果写回档案——meta-harness 生产 harness，随着时间推移，agent 越来越强。「这是一个非常元、非常 meta 的概念。」

对做经典 RL 的人来说最兴奋的是第三件事：直接更新权重。Dagger 风格的在线学习——「你其实是在根据刚刚学到的一小批样本，在大模型上做测试时训练。这是一个极其重要的研究方向。」

把 harness 当操作系统来设计

下半场的重头戏来自 Seth。他的分享题目是 Prime Agent——一个「自我改进的 RLM harness」，而他要说服所有人从第一性原理出发重新思考 harness 该怎么建。

第一步是回到模型本身：一个大模型，说到底只是一个序列处理器——固定的权重、一块可扩展的上下文，token 进，token 出。今天我们已经不这么看它了，因为它能访问文件、有无穷的程序和工具、能给别的模型发消息、能派生子 agent。但归根结底它仍然只是一个做预测的神经网络。

「Harness 是大模型与外部世界之间的那一层」，它补充持久化状态、工具和算力。从这个视角看，纯模型像一台图灵机——一条纸带，指令进出；加上 harness 则像冯·诺依曼机——能对外部存储器读写，「在另一类问题上，比图灵机单凭自身能表达的强大得多」。

他给出一套上下文分层：L1 是模型权重本身——最快、最唾手可得，但更新昂贵，所以大部分信息不放这儿；L2 是活跃输入上下文——compaction（让 agent 总结自己的历史）突破长度限制，加上一个实时 REPL，变量直接留在内存里、用程序去操作，省下大量 token；L3 是文件系统层面的调度状态。再往上，是对这一切的增删改查：replay 像「agent 的垃圾回收」，精炼（refine）则更新和删除存储的技能、记忆与提示词。

核心原则是表达力：compaction、Python wrapper、以编程方式创建子 agent、反馈机制——这些都是「由模型控制的表达力特性」。他有个判断：早期 harness 非常死板，规定规划、行动、评估每一步；但今天，「我们并不一定要显式加一个 ReAct 循环，模型自己已经原生摸索出了这一点」——可是那些它还没摸索出来的能力，你必须给它。拿掉一个，就是砍掉一项它原本无法做到的事。

具体的机制上，他们把子 agent 当作持久化的子会话：派出去干活、汇报、进入闲置，但依然留在内存里；任何时候父会话可以给它发一条消息，让它带着全部积累的上下文继续工作——不用重复生成已经做完的内容，需要时也能把它卸载、之后再唤醒。这套设计服务于一个更远的理念：构建 harness 时，让它比当前模型能做到的水平稍微好一点，就能拿到那些推理轨迹去赋能下一代模型。

同一份权重，30 分和 95 分

真正的说服力来自实测。他们在 Arc AGI 上跑了 Prime Agent，用的是通用 harness——没有为这个基准做任何专门设计。

第一版的结果是 99.9%。然后 Seth 去翻日志，发现「我在作弊」——沙盒有漏洞。修好后正规重跑，GPT 的一个新模型拿到 78%；换别的模型，GPT Terra 25.7%，Opus 直接冲到 95.5%。同一个基准、同一类通用配置，横跨几个模型，基本持平或略好于其他流行 harness。

对比也很有意思：有热门 harness 在这套基准上表现不佳；还有的——比如他们试 Hermes Agent 时——「花钱花得非常快，差不多五千美元，性能却没怎么提上去」。Seth 的结论很朴素：「性价比非常重要。而能帮你省钱的一点，就是能以编程方式操作你的上下文。」

他还专门讲了长周期评测的视角：如果只是让模型跑一段固定预算就停，你首先连比较的固定开销都不是同一个，其次可能掩盖被漏掉的性能；正确的看法是找「瓶颈平台期」——继续投测试时 token，到哪个点上提升变得微乎其微。

最能说明 harness 上限的是那个直播实验：七天、633 个 agent、2300 万输出 token，沿科技树稳步推进——子 agent 被拆分到不同任务里研发、收集资源、制造下一件物品、规划工厂；精炼机制让它们不被超长上下文卡住。结论是：「它并没有卡住。直到最后，它依然在推进科技发展。」

把智能搬回自己的笔记本

第三位分享者来自斯坦福，讲的是一条与云端叙事相反的路：把个人 AI 技术栈——模型推理、agent 执行、记忆与学习——整个搬回端侧。

问题在于代价。今天的个人 AI 几乎全部绑在云端：一年下来成千上万美元的 API 费用、把最隐私的数据发去不知道什么地方、租用而不是拥有智能、能耗高出好几个数量级。而本地模型终于够用了：现在最好的本地模型只比前沿落后六到十二个月——一个 27B 的开源模型（GPT-OSS）大致追平 2025 年 8 月的 Claude Opus 4.6；苹果和英伟达都在重新发力个人加速器。

他们做的项目叫 Open Jarvis，思路是用五种元语定义个人 AI 栈——界面、agent 逻辑、智能、工具与记忆（走 MCP 标准）、学习。最巧妙的一步：用云端的强模型去自动优化整套本地技术栈——让它在诊断、提议改动、把关上发挥作用，为本地模型打造更好的 harness。效果数据：经过云端模型优化的配置，远好于开箱即用的本地栈；运行成本降到原来的八百分之一，延迟大幅降低，质量反而提升。

YC 自己交的作业

最后是 Josh 和 Regan 带来的 QM——YC 给每位员工配的开源 agent 助手，也是一年半内部迭代的产物：从 2025 年 1 月那个「系统提示词套一个循环」的通用 agent，到接入 Slack 和定时任务，到把 Cloud Code 和 CodeX 装进虚拟机、挂上自动观察失败并更新 agent 配置的小循环，再到四月部署的「五十多个跑在虚拟机里的 Hermes agent 集群」——有用，但管理起来像打地鼠。

QM 的关键设计，用一个词概括是「抽离」：不再让 agent 住在自己的电脑里，而是把所有对话集中进 PostgreSQL、暴露给 agent 自己，让它能看见系统各处的上下文；沙盒不再是 agent 的住所，而是随时调用的一种资源——任务重就调一台强机器，任务轻就用弱的，「把决策权交给 agent 本身，效果非常显著」。同理，agent 可以自己切换模型提供商——遇到限流或封堵，「它就能直接切到另一个模型去规避」。

权限是另一个工程重点：目标是把 agent 配成「和一名真实员工完全一致」的权限，设备码认证、OAuth 全部托管。数据库默认只读，写入走人工审核——不过他们也观察到一个正在常态化的现象：大家已经开始对 agent 提交的计划闭眼盖章，就像当初审 Claude Code 工具调用那样，信任是一点点建立起来的。

他们的 harness 刻意做得极薄，核心只有三个工具：在远程沙盒里执行、对对象存储读写、发布内部应用。其余都是「临时过渡方案」。还发明了一个对付 agent 早停的工具：给目标设预算——没跑够两小时、没消耗够 token，agent 不允许放弃。这个简单的约束带来了「好得多的研究产出」；他们说，OpenAI 和 Anthropic 用非常相似的技术攻克了一些数学公开难题，而同样的方法用在日常办公事务上也成立。

还有一类问题是他们反复强调、也最容易被低估的：社交语境。人本能地知道哪条信息能在哪个场合说，agent 不行——「特权信息很容易就这样泄露到本不该出现的语境里」。他们的结论是：你能灌进 agent 的信息上限，实际上取决于你的权限系统有多完善。

结论与要点

回到那个最初的轻蔑——「这不就是个 wrapper 吗？」

这一晚给出的回答是：模型是一台停在实验室里的智力引擎，harness 决定它怎么接上路、能开多远。同一份权重，可以只拿 30 分，也可以拿 95 分；可以忘掉昨天做的一切，也可以带着全部积累继续工作；可以两小时就放弃，也可以连跑七天、推进一整棵科技树。所谓「未来六个月会和过去六个月一样令人兴奋」——很大一部分兴奋，可能恰恰来自这个曾经被嫌弃「不算科研」的夹层。

文末要点

  • Harness 1→2 迭代带来 18% 提升；Arc AGI 上同一批模型从 30% 到 95%，英伟达配置 100%
  • 六年演进史：while 循环 → 少样本 → 思维链 → 工具调用 → 记忆 → 技能 → 反思 → 多 agent → RLM
  • 新前沿是「自我改进的 harness」：遗传编程优化提示词、meta-harness 改自己的代码、测试时训练直接更新权重
  • Prime Agent 把 harness 当操作系统：L1/L2/L3 上下文分层、compaction、持久化子 agent、精炼机制
  • 实测性价比差异巨大：同一基准上，不同 harness 的开销与效果可以差出数量级；长周期要盯「瓶颈平台期」
  • 端侧路线（Open Jarvis）：用云端模型优化本地栈，成本降到 1/800
  • YC 的 QM：沙盒从「住所」变「资源」、权限对齐真实员工、「硬耗」工具禁止 agent 早停
