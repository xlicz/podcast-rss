软件不像房地产，它更像拍电影

OpenAI 负责 Codex 和 ChatGPT Work 的产品负责人 Tara Shah 讲了两件很少被公开谈论的事：她进公司时以为有一座装着 OpenAI 秘密战略的宝库，以及在新世界里，有一种写作她永远不会交给 AI。

Tara Shah 在 OpenAI 工作一年左右。在这之前，她在 Stripe 干了六年，是那里的前五位产品经理之一，其中好几年被评为整个 Stripe 排名前三的员工；再往前，她做过创始人、在 Sutter Hill Ventures 当过 EIR，也曾经是第二届 Thiel Fellow。

但让她这次访谈最有价值的一段，不是履历，而是她对「进 OpenAI 之前和之后」的描述。

她进公司时以为会有一座宝库，里面藏着 OpenAI 的独家秘密战略，就像以前的公司那样：一进去就觉得这是「支付宝典」，这是我们对支付和运营的理解。结果她发现，OpenAI 是完全开放的。关于世界应该是什么样、产品应该怎么做、模型应该怎么运行的各种想法，都会非常快地变成公开产品的一部分，或者对外发声的一部分。

硬币的另一面是组织形态。她说自己过去工作过的所有公司都是由创始人引领的，而 OpenAI 是「由各位创始人共同引领」——公司里的每个人，尤其是负责自己领域的，在某种程度上本质上都算是一个创始人。自上而下的指导极其有限。所以她刚进公司时很高兴：可以继续把自己当创始人，而且和市场之间的距离非常近。「在规模大一些的公司，你有时会觉得自己和用户需求隔了一层，但在 OpenAI，你完全不会有这种感觉。」

她失去的东西，和她唯一没变的东西

被问到「在这个新世界里，你失去了什么」，Shah 的回答很具体：宏大战略类的工作。

她解释了为什么。当市场比较静态、发展比较慢的时候，你有机会做宏大的战略规划，因为可预测性更高，你至少能理清所有拼图。支付就是一个例子——它当然充满变动，但也是成熟市场。你能说如果我压这个注，竞争对手可能会压另一个；也能非常严密地从第一性原理推导接下来的所有行动。事实上，那个市场的本质要求你必须这么做：赢家会比其他所有人都思考得更严密。

但现在这个市场里，未来太难看清了。它涌现性很强，变化极快，而且紧跟研究进展非常非常重要。所以在她看来，多产出、多靠经验实证，远比偏学术或偏理论重要得多。她过去工作过的很多公司都是非常学术、非常理论化的地方，写的是那种长篇大论的推演文档，差不多像博士论文。而现在取代它的是一句话：我怎样才能以最快的速度，做出一个能拿给用户试用和测试的东西？

她说这个转变一开始非常不适应。她会怀疑自己是不是没做足功课、考虑得不够周全。但结论是：你必须去尝试各种东西，尽可能多地去学习。而这意味着你要做的思考，是尽可能精准地明确你的核心假设是什么——那个需要去验证的最具体、最重要的核心问题到底是什么。至于其他一切构想出来的宏大战略，都不相干。

不过她认为 PM 的核心并没有变，反而变得更中心了：针对你的产品，你需要去问的最本质的问题是什么？决定你产品成败的核心因素是什么？你打算怎么验证？你怎么看验证的结果？你怎么把结果反馈回闭环里，迭代你的假设，然后再跑一遍？

「你看，这才是 PM 一直以来真正的工作。」而且不只是 PM。她说，现在能明显看到工程经理、工程师、数据科学家、设计师都把精力转到了同一个地方：问题定义和验证闭环——我们到底在做什么，以及我们怎么知道它有没有奏效。那些繁文缛节正在褪去，留下的只有这件事。

「按模型现在的水平做会失败，按一年后的做也会失败」

访谈里最有传播力的部分，是 Shah 描述 OpenAI 内部的几条「文化梗」，而它们其实都是产品纪律。

第一条是「我们做的是不是两三个月后模型所在的位置？」她把它说得毫不含糊：

如果你按模型现在的水平去开发，你会失败。如果你按自己设想的一年后模型会达到的水平去开发，你也会失败。这两种结果都同样是错的。

所以唯一的开发方式是按两到三个月的节奏来做，并且要在产品架构上给模型让路——模型会变得好得多，你必须把它作为产品的核心来考虑。

第二条是「这加速到极致了吗？」第三条叫「你开始静脉注射了吗？」——意思是，你是不是全天都在用这个产品来处理自己的事情？Shah 说，这三条合起来构成了一套完整的自查：你想做的事情的范围和规模够不够大？推进速度是不是尽可能快？你有没有在用自己的品味判断这东西行不行、是不是大家真正想要的，并尽可能收集反馈闭环？

她还引了一句她很难忘的话，来自 Kevin Weil 当年在播客上说的：现在的模型，是以后最差的。 这句话听起来简单，但真正理解它很难。「现在说这句话几乎成了陈词滥调，但这是事实。」

ChatGPT 里那三个开关，以及它们底下是什么

Shah 负责的另一个产品是 ChatGPT Work。她把这个产品目前的形态讲得很清楚。

你打开 ChatGPT，会看到下拉菜单里有 ChatGPT 和 Codex，还有 Chat 和 Work 的切换按钮。她的解释是：在 ChatGPT 和 Codex 之间做选择，本质上是在选你想不想待在更偏向开发者的界面里。你是 Codex 用户，就继续用 Codex，什么都不会落下。但如果你是个 ChatGPT 用户，想知道这些新的 Agent 式能力到底是什么，那你大概率会用 ChatGPT 模式。

Chat 模式就是你熟悉并喜爱的聊天，只是每次都会带上越来越好的模型和越来越新的功能。但在 Work 模式里，底层其实就是 Codex——他们去掉了部分编程界面（比如不会有工作树突然弹出来），但做事的能力是一样的。她举的例子是生成一个极其复杂的财务模型。

她说看到有人，特别是企业财务团队，用 Work 模式做出了极其出色的成果：原本要么得靠人工，要么得依赖团队里某个人的专长，现在变成了全团队都能搞定的事。

但真正的北极星目标不是这三个选项：「用户不需要在所有这些不同的选项之间做选择。理想情况下，这里没有任何切换按钮。」你的动作只是来到输入框、打上任务，然后系统自动选好合适的 harness、挑好合适的模型，把那件事做成。做选择的责任不应该落在用户头上——用户不该既要搞懂自己想干什么，还得弄明白产品的限制和能力。

她也解释了为什么过渡期看起来不会那么完美：节奏太快。可能有人会说「咱们试试 Codex 吧」，然后它就火了，有了一千万月活，接着大家就得想「等等，我们有 ChatGPT，又有 Codex，我们该怎么弄」。你必须随着哪些行得通、哪些行不通去调整。

在这个背景下，她讲了一个跟大多数产品人直觉相反的判断。在以前的很多公司，打磨是王道——把每一个 UI 交互、每一个细节彻底做对，远比早早发布重要，因为时间对最终结果的影响没那么大。但在现在的产品体验里：「当你非常确信它具有颠覆性的时候，把产品交到用户手里，远比追求完美要好得多。」

Codex 的风向是怎么变的

最近几个月，科技圈的风向明显从 Claude Code 转向了 Codex。Shah 被问到内部到底发生了什么转变。

她的回答是一个几乎什么都没说的答案，而这正是重点。她引了一句禅语：「悟到前挑水砍柴，悟到后还是挑水砍柴。」Codex 这款应用最初做出来并负责开发的团队，同样是超级关注用户、迭代周期极短、真正把它当主力工具用、把每个细节做好。外界和 Twitter 上的人开始意识到这点，用户也开始注意到。但团队一直都非常关注用户，非常专注在那套迭代上。某种程度上，这只是市场终于跟上来了。

她把功劳完全归给团队：团队里几乎每个人，尤其是桌面端团队，都像创始人一样做事，在意每一个环节、每一个细节。当他们发现某个地方应该做得更好时，就会非常独立地把它做出来、跑通上线；如果内部测试反响不好，就继续迭代，最后才推给外部。

主持人注意到一个更普遍的现象：角色边界正在消失。工程师在做 PM 的工作，可能还在发布原型、写代码、推到生产。很多设计师和marketing人在问：我现在到底该负责什么？

Shah 说她在初创公司工作时最喜欢的一点就是角色边界非常少——「可以说一切都归你管，也可以说一切都不归你管，最终你只对成功负责。」Stripe 当时就是这样，工程师、产品经理、设计师之间没有任何界限，每个人什么都能做。她说现在大家的能力终于跟上来了。

但她给这个趋势加了一个必要的约束：得有人去核心负责一件事。 这个产品到底有没有人在用？这是不是大家想要的东西？质量高不高？不管这个人是工程师、设计师还是 PM，总得有人是 DRI。

她也诚实地说出了这个模式对她的代价。她非常热爱 PM 的专业手艺：「有时候可能有些疑问，正源于我太热爱自己领域的专业手艺了。为了把事情办成，采用这种更灵活的团队协作方式，我是不是就失去了提升和打磨自己专业手艺的机会？这个问题我真的没有答案。」

她给了一个部分答案：手艺的某些部分，实际上正被模型非常高效地接管过去，甚至可能比个人做得更好。你的手艺就从「能做某项非常具体的工作」，转变成「把它应用到产品或专业的其他部分」。

软件不像房地产，它更像拍电影

Shah 谈「闭环」这个概念时，打了一个很准的比方。她说未来的工作会越来越像掌舵，而不是划桨：可以协同的 agent 替你做大部分的划桨工作，而你的角色越来越偏向于把控方向。

而且这个掌舵的层面会一直往上升。以前掌舵的层面是我写了这行代码；现在是「我在指挥一个更综合的任务」；将来会到目标层面，甚至更高。但归根到底，依然需要人判断方向定在哪儿。

这里她提出了一个容易被忽略的点：方向不只取决于数据告诉你什么，很大程度上是要做出有主见的决断。「我觉得有时我们会低估直觉的力量，甚至是低估我们希望未来成为什么样子那种积极决断。比如去构想我希望产品呈现这个样子——并不是因为反过来的策略不可行，而是因为我希望世界朝着我推动的方向发展。」

主持人追问：如果人人都用同样的工具，那我们不就都在做一样的东西了吗？

她的答案是「非对称优势在人身上」，并用时尚打比方：确实有那种人人都能穿、满足基本功能的功能性服装，但你想穿什么，很大程度上是想借此表达自己的个性。一件衬衫之所以能表达态度，仅仅是因为它可能和所有人穿的不一样。

然后是整场对话里最好的一句比喻。她引用了 Patrick Collison 关于软件的表述：软件不像房地产，不是你投钱进去就能产生价值的；它更像拍电影，你可以在一部电影里砸很多钱，但那并不能保证电影一定会成功或好看，它需要某种作者式的表达，或者某种主见与艺术性。

她接着引了 Marty Cagan 的观点来补全这个论证：当你对某个产品或功能有了想法，最终做出来的东西很少会是最初那个想法，你必须经历一个完整的探索过程，才能真正搞清楚它该做成什么样。所以她认为迭代闭环转得越快，你形成直觉的能力、获取形成直觉所需信息的能力、然后利用这些直觉与人和 AI 配合付诸行动的能力，才是关键。

野心正在成为唯一的差异

Shah 说，现在大家都能非常轻松地搞定所有简单的事。简单的事变得超级简单，困难的事也变简单了。于是：「现在把人和人、公司和公司区分开的，就只是他们能有多大的野心了。」

她观察到，最擅长使用 AI 工具的人，并不仅仅是用它把机械性的任务自动化，而是用它扩展自己能够做的事情的范围。她用一个旧概念来解释：在过去，所谓的独角兽人才，是那种产品感非常敏锐、同时又刚好是工程师、可能还兼具设计能力的人。因为这种人能切实消除职能之间所需的沟通层级，能自己快速构思并做出东西。

现在这种能力普及了。她说自己可以快速做出一套设计，做个最初的 demo 原型，摸索出适合它的定价模式、把所有情景都建模算一遍。结果是「你不再真正受限，你的野心不再受限于你能亲自执行什么、你能沟通清楚什么」。

而最难的部分不是能力，是打开思路。她引了 Patrick Collison 网站上那个叫「Fast」的项目清单——那里列着一大批在极短时间内完成的、野心大到不可思议的项目。在她看来，那份清单今天的意义已经变了：它让人意识到，那些事情现在都在你的能力范围之内。

「就像你所说的，最难的部分其实是想起来去试一下。这就像一个新习惯，像是一个我们需要在大脑里建立的新东西。」

她还给 PM 这个角色加了一个很少有人提的职责。她引用 Tyler Cowen 的说法：大多数人都低估了「去找另一个人说『嘿，你手头这件事更有野心的版本会是什么样』」所带来的影响。所以在她看来，拉高其他人的野心，或者提醒他们这里存在什么可能性，是产品经理角色中非常重要的一部分。

两种写作：以写作为思考，和以写作为汇报

访谈里被特意要求讲的一段，关于写作。提问的人告诉她，Tara 写的文档堪称标杆，请她讲讲怎么做到的。

她的回答建立在一个区分上。她说自己在工作中有两种类型的写作：一种是以写作为思考——写一份简报，讲我们为什么要做某个产品、为什么要采取某个策略，或者提出一个比较犀利的观点；另一种是以写作为汇报——总结团队这周进展、发一份相关报告、写一份特定发布的计划。

第二条她非常乐意自动化，一直在用模型让它尽可能简单。第一条她永远不会自动化：

梳理大纲，把它写成连贯的文字，删减和编辑，不断迭代的过程，是我理清思路最重要的步骤之一。

她说大多数人其实会一概而论——「我绝不会用模型来写作」或者「我总是用模型来写作」——而这在她看来两种都错了。应该尽可能多用模型的，是以写作为汇报；而不能用的，恰恰是你通过写作来思考的那些时刻。

她的操作原则非常具体：如果我要让别人读我的文档，我自己起码得先读过同样多遍。 会议同理——如果我要召集一群人开会，我需要先把大家在这场会议里要花的总时间准备出来。所以她虽然会用 AI 调研、填数据、抓数据、反驳想法，但起头和收尾都由她自己完成，也不依赖模型润色文笔。

然后她说出了一个更大的变化，这个变化她自己都觉得有点不适应。

过去她习惯在文档里思考，然后把思考转译成某种用于展示的产出物——那是她表明自己已经把问题想透、以及团队接下来该往哪走的方式。而现在，她更多是看原型图而不是文档。

原因是：「长文档不再代表你把事情想透了，因为你很容易就能写出一篇长文档，反而表明你根本没想透。」

如果她有一个大家可以去试用、去交互的东西，或者更好的是拿出了结果——我们试了这个、跑了 A/B 测试、这是结果——那会是比文档好得多的沟通工具。所以她说自己现在依然一直在写文档，几百篇，但她写是给自己看的。「那不再是交流和沟通的最佳方式。」

她还分享了一个关于文档的实操技巧，并且说这几乎是「作弊」：永远正确的做法是把文档写到百分之七十的完成度，然后去找那些需要他们支持的人，一起把它从百分之七十做到百分之一百。理由是很少有优秀的人愿意去面对一个打磨得完美无瑕的成型想法——面对一个完美无瑕的想法，他们的新想法根本插不进去；反而是那些有棱角、更粗糙的东西，他们也能和你一起打磨。

知识工作不是写代码

在访谈的最后一段，Shah 讲了一个她认为被严重低估的产品问题：知识型工作和写代码，从根本上就不同。

写代码非常以产出为导向。当你让它执行一项编码任务时，你可以通过测试来验证它完成得是否正确：试运行一下，看能不能跑通。也就是有一种方法根据产出来验证它。

但知识工作不同。「我不能单纯只看最后的 PPT，看到上面的数字说『哦，成功率大概百分之九十』，就真的信了。我真的需要去思考其中的过程、输入的信息、推理逻辑，以及它是如何一步步推导出来的。」

所以产品形态上要做的很多工作，是让产品去适应知识型工作：把重点更多放在让 ChatGPT 成为你的协作者，让你能看到所有进行中的工作、看到它的引用来源和输入信息，帮你和模型一起经历推导过程，最终得到那个产出。这样你最后才能判断：这个东西是对的、是好的、是有用的。

她认为这体现在两个层面：一是 UX 上，过程中应该看到更多引用来源、看到它是如何推导出那些数据和最终状态的；二是思维链里的推理这类底层机制。而她自己提出了一个开放问题：对话流这种非常适合写代码的界面形式，对知识型工作来说，是不是也是查看所有这些内容的合适形态？

主持人补了一个很准确的场景：在一场高管会议上，你想说明「这是计划，这是我觉得我们应该做的事情」，其中很大一部分是要让他们看清你为了得出结论所做的工作、所有的步骤。本质上就是工作证明。 而工程那边恰恰相反——我不需要知道你做的所有微小架构决策，它通过我们现有的所有测试了吗？

Shah 认同这个差异太大了。她还补了另一个关键维度：上下文。「它拥有做你想让它做的事情所需的上下文吗？它知道吗？它能看到你的邮件吗？它能看到你所有的 Notion 文档吗？」

人类大脑还剩什么

访谈最后，Shah 被问到那个几乎所有站在前沿的人都会被问到的问题：随着 AI 越来越强，人类的大脑在哪些方面会继续保有价值？

她的答案分成三层。

第一层是责任。 人类会继续在「承担责任的主体」方面保有最大价值——到底由谁来对最终的结果负责？「在某种程度上，你可以把你写作的 agent 当成是你的下属。但最终谁来对最终产出负责？质量高不高？他做出的东西、说出的话是不是你想要的？这肯定依然得由人来承担。」她说这在那些受到高度监管、或者需要直接由人来对接的行业和场景里尤其明显。

第二层是表达。 她又回到了电影那个比喻：软件不像房地产，它更像一部电影，你投了钱也不一定能拍出一部好电影，最棒的电影往往不是预算最高的那些。既然做软件带有一种艺术性、主见和表达，你能感受到它出自某个人或某个团队的创作，那这一部分依然是非常人类特有的。你选择做什么、给人的感觉如何，完全是一个属于人类的问题。

第三层是关心和联结。 这一层她说得最实在：「我工作中的那部分依然非常人性化，而且实际上变得比以往任何时候都更重要。就是你和团队里的其他人交流，共同找出大家如何对一个领域产生热情，你们如何一起学习、一起工作，如何激发彼此更大的抱负。」

她还讲了职业生涯里一段不寻常的经历：她曾在 Sutter Hill Ventures 当 EIR，那是一家有意保持低调的机构，官网上一片空白，却参与了硅谷很多最标志性的成功。让她印象最深的是：大家往往把「找到 PMF」和「打造一家数百亿美元估值的公司」看作玄学，是运气、是碰巧、是一堆因素凑到了一起。但那家机构的合伙人 Mike Speiser 已经做到过好多次。「所以显然是有门道的，显然有一套路线图可以让这件事成为可能。」

她从中得到的最大收获，恰好印证了前面关于「工作证明」的那段讨论。她说 PMF 固然重要，但她之前严重低估了产品与营销的契合——你讲述这个产品的方式和营销它的方式，甚至可以走在实际把产品做出来之前。这种叙事、这种定位，才是真正该先去测试的东西：去向一百个人做宣讲，把那套说辞打磨得尽可能精炼，然后也只有在那之后，再去确定产品的具体形态。

会跑起来的网站，和一条置顶的座右铭

访谈里最生动的一段演示，是 Shah 讲她自己怎么用 AI。

她说现在经常建网站。不是那种「做一个真正的工作产物」的网站——她给团队建过一个网站当游戏用，大家通过它一起玩了一个游戏；她前不久去背包徒步，就专门建了一个路线网站，能追踪每个地方的海拔，队里每个人都把自己的食物录了进去。

她说这实现了 Alan Kay 在六十年代提出的那个「有价值的个人软件」的梦想——真正的个人电脑，是拥有个人软件的电脑。区别在于门槛：「有了网站功能，真的就是一句 prompt 的事儿。我只要给它一句 prompt，说帮我做这个正好能完成这件事的工具，它就直接做出来了。」

它还会自动托管，可以选择公开、只对团队开放，或者只对自己私密。她说自己以前往往要创建很多产物，文档、表格之类，现在随时都在做网站。她还推荐了 Codex 里的 /visualize：直接让它把某件事的数据拉过来生成一个非常惊艳的可视化。

至于她自己使用 AI 的方式里最值得带走的一条，可能是她提到的那个「温馨小软件」的方向。被问到最喜欢的 OpenAI 之外的 AI 产品时，她说是她朋友专门为她做的产品——一个能把任何内容变成播客的 AI 应用，直接以新单集的形式放进你订阅的播客信息流；还有一个给一小群朋友的私密社交网络。「这完全就是我认为未来的样子，也就是人们做出来的软件，刚好能满足自己和朋友的需求。」

访谈的最后，她引了一条自己置顶在社交主页上的座右铭，来自 Toni Morrison 的文章《The Work You Do, The Person You Are》：

不管是什么工作，都要把它做好，不是为了老板，而是为了你自己。是你造就了工作，而不是工作造就了你。你真正的生活是和家人在一起。你并不等于你做的工作，你就是你这个人本身。

她说自己每次打开社交媒体，看到它还在那里提醒自己。

文末要点

  • OpenAI 没有密室里的总体规划。 她进公司时以为有一座宝库藏着独家战略，结果是完全开放的；真正意外的是自上而下的指导极其有限，每个人在自己领域都像创始人。
  • 她失去的是宏大战略，得到的是验证速度。 静态市场要求你把所有步骤严密推演；现在唯一值得做的思考是精准定义核心假设和验证闭环。「按模型现在的水平做会失败，按一年后的水平做也会失败」，唯一可行的节奏是两到三个月。
  • ChatGPT 的 Work 模式底层就是 Codex。 三个开关（Chat / Work / Codex）是过渡形态，北极星是取消所有切换——用户只输入任务，系统自己挑 harness 和模型。
  • Codex 的转向不是内部发生了什么变化。「悟到前挑水砍柴，悟到后还是挑水砍柴」——团队做法一直没变，只是市场终于跟上了。
  • 软件不像房地产，更像拍电影。 投钱不等于出好片，最贵的电影常常不是最好的。这个类比同时支撑了两个判断：非对称优势来自人的表达，以及人类最终仍是承担责任的主体。
  • 区分两种写作。 以写作为汇报的部分尽可能交给模型；以写作为思考的部分（起头、收尾、删改、迭代）绝不外包。她的原则：要别人读的文档，自己先读同样多遍。
  • 长文档不再证明你想透了。 生成一篇长文档太容易了，反而成了没想透的信号。她自己写的文档现在基本只给自己看，对外沟通改用原型和实测结果。
  • 知识工作和写代码的验证方式根本不同。 代码靠测试验证产出；知识工作必须看到过程、输入、引用和推导链条——产品形态要围绕「让你和模型一起经历推导」来设计，而不是围绕对话流默认界面。
  • 拿不准该做什么的时候，先测叙事。 Sutter Hill 的教训：产品与营销的契合可以走在产品之前，去向一百个人讲那套说辞，把它打磨精炼，然后再确定产品形态。
