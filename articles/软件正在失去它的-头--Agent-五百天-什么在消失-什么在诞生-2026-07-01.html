软件正在失去它的"头"：Agent 五百天，什么在消失，什么在诞生

副标题：当所有软件都不再需要界面，最该恐慌的不是设计师，而是那些还在为上个时代的问题写代码的创业者。

2024 年 1 月 1 日，十字路口做了一期开年播客，叫"Agent 元年"。到现在，差不多五百天。

五百天里发生了很多事：第一百天，Claude Sonnet 3.5 发布，第一次让 Agent 有了可用的执行基础；第三百天，Claude Code 上线；第四百天，OpenCL 发布，把 AI Agent 塞进了用户每天用的 IM 工具里。

但最值得聊的不是这些里程碑，而是其间生长出来的一种共识：软件正在失去它的 GUI——那个我们花了二十年打磨的前端界面，正在变成 Agent 的负担。

真格基金投资总监天杰在三个月前写了一篇文章，标题是"我们或许不应该再投资 GUI 思维的软件"。这句话在创投圈刷了屏。五百天后，他和独立开发者藏师傅、十字路口的科技坐在一起，想搞清楚一个问题：当软件不再需要"头"——不再需要界面，只剩下数据、工具和 API——创业者该怎么重新理解"产品"？

软件为什么需要失去"头"

天杰当时写那篇文章时特意加了"思维"两个字。

他的逻辑很直白：过去的软件是为"人使用"而设计的。GUI 的存在是为了降低人类的使用门槛——按钮、菜单、导航，都是给人类的认知缺陷做补偿。但当 AI Agent 开始替代人类执行任务时，GUI 反而变成了负担。Agent 不需要看按钮，它只需要知道这个软件有什么能力、怎么调用。

藏师傅的实践证明了这个判断。他的 Code Pilot 项目维护着几十万行代码，用户规模不小——"我在五百天前绝对想不到自己能做到这个程度"。他原来只是个"懂一点基础前端"的人。

但更让他意外的是另一件事："我现在连写内容都交给 AI 了。之前我是坚决不会用的，但现在发现这种坚持没有意义。"

他的判断很冷酷：对于信息传递型的写作——公众号文章、新闻、观点表达——AI 有时候写得比人好。"怎么样信息传达效率最高、摩擦最低，它一定会以这个方向演化。"但他也画了一条线：文学性创作，AI 还不行。

谁最该开放 CLO？

当软件不再需要界面，一个新的问题浮出水面：用户怎么触达这些"无头软件"？

答案是 CLO——Chat-Language Optimized Interface，或者 COI，Chat-Optimized Interface。本质上就是让软件把自己的能力通过对话接口暴露出来。肯德基、瑞幸已经在做这件事了。

但所有人都盯着同一家公司：微信。

藏师傅说这句话时几乎没有犹豫："当然是微信。你在所有事情都可以被 AI 自动化的时候，跟人的沟通、跟客户的沟通，依然在用非常痛苦的 GUI 点进去打字回复。"

不过他并不期待微信会改变。"我可能不会期待一个传统服务进行 COI 转型，我会期待一些新的、完全基于 Agent-first 的服务出现。"他举了一个例子：他现在用 Manus 规划旅行，而不是小红书。

天杰观察到一个更微妙的变化：年轻人开始在抖音上聊天了。"抖音聊天的 DAU 是一个亿。内容消费在哪儿，聊天就会在哪儿。"扎克伯格曾在内部分享中承认低估了 TikTok 的冲击——他以为 TikTok 只是内容平台，但"我看到一个内容分享给你，就自动开启了对话"，这是 WhatsApp 的命门。

对微信来说，这是同一把刀。

技能地狱与技能经济

聊到 Skill 时，藏师傅推荐的是自己的 PPT Skill。"第一个是我付出心血比较多，第二个是大家确实需要。"但他也承认一个尴尬的现实：很难向 C 端用户收费。

"用户心想，我已经花了 Token 的钱了，为什么还要再给你钱？只有当他真正看到了优质结果，跟其他 Skill 比较之后，他才可能反过来觉得这个东西值得付费。"

天杰分享了她的 Skill 使用场景：会议总结、播客辅助、还有一个叫"Grill Me"的 Skill——"当你有一个问题想不明白的时候，让它来向你提问，用各种角度榨干式地提问，把你脑海里的想法全部引导出来。"

但她也指出了一个关键问题：AI 自动总结的 Skill 缺少一个环节——"你调整的过程"。AI 是在猜你的需求，而好的 Skill 需要人和 AI 之间反复磨合。"这就是为什么那些自动帮你总结 SOP 的功能，生成的东西不一定符合你的要求。"

OpenCL 改变了什么

OpenCL 的出现被三人视为一个分水岭事件。

在 OpenCL 之前，AI Agent 要么在 CLI 里运行（对普通用户太硬核），要么被塞进各种不自然的界面里。OpenCL 做了一件事：把 Agent 放进你最熟悉的 IM——WhatsApp、Slack、微信。

"它第一次让你感觉对话的不是一个工具，而是一个人。"天杰说。藏师傅补充："OpenCL 至少证明了 CLI 对大部分用户还是很难用的……它以非常暴力的方式帮大家完成了认知转变。"

但问题也在：安装困难，莫名其妙宕机后用户没有动力重新启动。

下一个五百天

问到对未来的判断，藏师傅的回答是："我们不知道五百天以后还会发生什么。今天说的判断大概率都是错的。"

这不是谦虚。他经历过太多次"犹豫了一两个月，发现已经来不及了"——五百天里频繁出现这种情况，"未来五百天依然会这样。"

天杰给了另一个视角：也许产品形态不会变，但后端生产效率增长了几百倍，前端会涌现出完全不一样的结果。"下一个抖音未必是别的形态，下一个抖音可能是十倍产能的抖音——生产变成工业化，就像过去养猪是每家每户的小作坊，电力出现后变成了集约化养猪场。"

这不是一个关于技术突破的预言，而是一个关于产业组织的判断。当生产成本降到足够低，不是产品形态在变，是谁能活下来的规则在变。

文末要点

  • GUI 思维的核心缺陷：它是为"人类使用"而设计的，当 AI Agent 成为执行主体时，界面变成了多余的中间层
  • CLO/COI 的本质不是"聊天机器人"，而是让软件能力通过对话接口暴露——微信不做，自然会有别的平台做
  • Skill 经济的瓶颈不在技术，在信任——用户需要亲眼看到优质结果才愿意付费，这是一个缓慢的建立过程
  • OpenCL 的真正价值不是技术架构，而是把 Agent 放进了用户每天已经打开的 IM 里，完成了最难的一步：改变使用习惯
  • 下一个五百天最确定的不是技术路线，而是"犹豫一两个月就来不及"的速度——决策质量比技术判断更重要
