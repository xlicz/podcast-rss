「模型能力已经够了，要卷就卷 infra」

Runta 创始人戴冠兰：当系统最底层的执行单元变成概率性的，基础设施这层怎么构建？

戴冠兰在 35 岁这年拿了 2000 万美元种子轮，a16z 领投，Jeff Dean 和李飞飞以个人身份做天使投资人。这家公司叫 Runta，团队十个人左右，背后有成百上千个 Agent 在干活。他要回答的问题只有一个：当 AI 智能体比人还多的时候，它们跑在哪、怎么管。

拿到 Jeff Dean 的钱之前，戴冠兰先回答了他一个问题。

Jeff Dean 问他：如果系统最底层的执行单元变成了概率性的，那基础设施这一层要怎么构建？

这个问题戴冠兰当场没有答案。他说这个问题确实很难答——因为过去几十年系统工程的全部根基，都建立在软件是确定性的这个前提上：同样的输入进同样的系统，输出基本一样；出错了就是异常，异常在软件时代是可以枚举的。重放、幂等、容错、恢复，全都长在这块地基上。现在大模型把这块地基抽掉了：每一次执行，Agent 生成的下一个动作都不同，你永远没法用预定义的规则穷举它。

戴冠兰的答案是：把复杂度压到 runtime 层去做。

执行层成了系统工程里最难的问题

戴冠兰的履历几乎是为"从零构建一代基础设施"而写的。他是 Cloudflare Edge 平台的早期工程师和技术负责人，参与过边缘缓存、WAF 和早期 Workers 计算平台的搭建；之后加入 Kong，做企业网关和云，是创始团队的第一位工程经理。加起来十几年，都在给上一代互联网打地基。

他举了一个数字说明那种规模的复杂度：在 Kong，每天经过的 API 请求有上千亿次。在这种规模下，哪怕出错概率只有 0.000001 的事，也会变成必然会发生的事。基础设施这门手艺，处理的恰恰就是这类问题。

所以他的判断有分量：上一代 infra 解决的是"物理机到底怎么跑"，这一代要解决的是"执行本身怎么做"。Agent 的形态已经变了——以前一个 chat 是几分钟、几个 turn，现在一个 Agent 跑几个小时甚至几天。隔离、分叉、迁移、热迁移，这些分布式系统里的经典难题，现有基础设施一个都没解决好。

他自己也承认，这件事很难做。但这正是 Runta 的存在理由。

从 Token Maximizing 到 Minimizing，只用了半年

这期对话里最具体的产业观察，是 Token 使用观念的反转。

戴冠兰还原了时间线：thinking 模型出现之后（他指 o1 这一代带思维链的复杂推理），企业管理者开始相信"用更多 token 就更聪明"。这个逻辑被外推成组织管理：一个员工消耗的 token 越多，说明他越 active，这是一个可度量的 KPI。一旦可度量，就能围绕它推动组织变革。Meta 和亚马逊是最早把这套玩法在组织里推开的一批。

他去年底走访前沿客户时，在一家 AI lab 的墙上看到一块显示器，专门显示本周哪个员工 token 用量排名最高，前几名还有奖励。演化到极致，Meta 和 Stripe 把 token 使用量和业绩考核直接挂钩。于是他看到了最极端的故事：有员工为了刷榜，故意写一些没用的 loop 把用量刷上去，不管什么任务都用最强的模型。

反转只用了三到六个月。Uber CEO 公开说，四月就把全年的大模型用量用完了——"我们到底收获了什么东西？"企业开始意识到两件事：点火的阶段结束了；以及模型真的很贵，"大家远远低估了模型的真实价格"。

Runta 自己的管理也随之调整。最早他们无限 token、随便用，让员工形成"token 是免费的"的感觉。现在改成阶梯制：先订阅几个最大的 Ultra Plan，用完了要说明用在哪；真需要一个月花十万美金的人，走流程——"加入一些流程上的小摩擦，让你感觉到这个东西不是 free 的"。

a16z 为什么为一家种子轮公司写博客

戴冠兰提醒了一个细节：a16z 很少为一家这么新的公司专门写博客解释"为什么我们投它"，而且这篇是 partner 级别的 Martin 亲自写的。

他理解 a16z 看到了什么：这不止是一个 feature 或一个产品，而是平台级的机会——一次 compute 的代际变化。从客户端/服务器到数据中心，从物理机到虚拟机再到容器化，每次迁移都是代际变化。这一次，被托管的对象从软件、服务变成了 Agent 本身。如果这个判断成立，就是一个巨大的平台机会。

那为什么这个机会属于创业公司，而不是公有云？戴冠兰的类比是 GPU 浪潮：上一波数据中心是 CPU 搭的，这一波以 GPU 为主，所以冒出来一批 New Cloud——传统数据中心的架构需要为 GPU 整体重建。同样，现在所有公有云的计费模型、整套基础设施底座，都是为 SaaS 和传统软件设计的。公有云会往这个方向迭代，但它的机架模型和内部包袱在打架。这类机会历史上属于从底层重建的创业公司。

模型厂商也做不了。Anthropic 已经发布了 Agent 管理相关的系统，模型公司肯定会做这件事——但企业落地时不会绑定一家模型，也不会绑定一朵云。多模型、多 harness、多云，本身就是在分散风险。更根本的是，大模型公司做一切事情都是为了拿到信号改善模型本身。模型能力和 infra 底座是两个职责不同的生意。

至于 E2B、Daytona 这类 sandbox 方案：技术底子是 Firecracker，来自上一代 serverless 产品，解决的是十五分钟到一小时内的短任务隔离。这套东西很好，但 Agent 跑得越来越长之后，什么时候用 GPU、怎么动态迁移、内存怎么动态伸缩，上一代方案已经碰到瓶颈了。他认为必须从第一性原理出发，从下往上搭整套系统，才可能真正回答"未来十亿个智能体往哪跑"。

一场必然发生的灾难

聊到权限管理时，戴冠兰做了一个预言："未来十年必然会有灾难性的邮件通过 Agent 发出去，难以挽回。Mark my word。"

他把前提说得很清楚：包括他自己在内，大部分人都在用"安全换便捷"。主持人柯记分享了自己的滑坡过程：一开始让 Agent 写草稿、自己点发送；得到信任之后，连草稿都懒得审了；现在边界已经被一点点吞食，"反正就随便看吧，我相信你不会乱搞"。

只要发生一件灾难性的事——哪怕不是发生在自己身上，是发生在别人身上——之后所有人都会变得非常谨慎。

Runta 做的不是传统网络安全——不做主动扫描、特征匹配那套。他们做的是管控：让 Agent 在可控的边界内执行，最坏的情况能恢复，每一步可以审计。戴冠兰的框架是：安全本质上是"你有多信任这个智能体"。信任不是用安全框架框出来的，而是靠执行底座给的——企业知道最坏能坏到哪、能恢复、能追责，才敢把真正的生产权限交给 Agent。

他提到一个现实数据：一项安全调研发现，世界 500 强公司里，大部分使用 Agent 的企业已经发生过机密或客户信息的泄露。

而且模型侧解决不了这个问题。只要还是 Transformer 架构，就还是 next token prediction——模型无法区分给它的是"指令"还是"数据"，在中间插分隔符之类的防御手段都有办法绕过。所以必须有人从 infra 侧给这套非确定性的架构加上确定性的约束。

暴论与信号

戴冠兰在节目里下了两个明确的判断。

第一个暴论："模型能力已经够了，要卷就卷 infra。"他的理由是开发者视角的边际变化：最新的模型和他之前用的 Claude Opus 相比，"对我们来说没有本质上的区别"。爬坡已经开始放缓。模型能力到位了，基础设施和 harness 整块没跟上，所以还没落地。

第二个判断关于开源闭源：开源模型会一直往上爬坡——Kimi 已接近 SoTA 第一梯队，DeepSeek 最新模型在多快好省上持续进步。他预判模型最终会商品化，像今天的电和水，变成"不那么性感的生意"——这也是今天大模型公司高估值背后的最大担忧。他对时间的判断是：一年到五年之间。

起飞信号他给了最朴素的一种：企业客户排队想用 Runta 的服务，但他们因为团队交付能力有限，把优化重点放在 agentative 团队上，订单先缓一缓。早期营收不是他的优化目标。

有意思的是他选择的客户画像：不是大企业，而是 agentative 公司——造 Agent 给别人的 agent builder，以及剪视频、做营销的垂类 Agent 公司。原因是这些客户"有量"：服务好一个，就能间接服务成千上万个 Agent。

产品上，Runta 已经抽象出一些标准化模块：执行平台、沙盒调度、token 分析。他举了一个正在用的功能：把任何 harness——Codex 的、自研的——跑到他们的执行平面上，系统会分析这个 harness 到底在哪浪费了 token、怎么浪费的，再生成提示词帮开发者迭代 harness。"harness 在上面跑，我告诉你怎么样把 harness 跑得多快好省"，形成一个闭环。

用 Agent 写代码，靠人做架构

Runta 内部 95% 以上的编码工作已经由 Agent 完成，"入门程序员那些工作基本上全用 Agent 代替"。但戴冠兰明确划了一条线：架构设计、API 设计、模块解耦这类依赖底层判断力的工作，仍然需要人类工程师。

被问"用 Agent 写代码去治理其他 Agent 有没有风险"时，他直接承认："肯定有风险。"应对方式是天天用自己的平台、用自己的 Agent 跑在自己的执行环境里做自我迭代——他自己是公司里用 AI 最激进的人。

关于工具选型，他的团队模型路由完全交给工程师自己决定，共识是"工程师最有体感"。Codex 是他的主力，他对 Claude Code 的评价是"吭哧吭哧干活、质量很高，像个德国人"，而另一个产品"很 chatty，像个美国人"。团队甚至自己手搓了一套 harness，效果不错——这也让他反思：harness 的护城河可能没那么高，未来每家企业可能都会搭一套自己的。

他给年轻人的职业建议同样有信息量。核心一条是选浪潮：加入 Cloudflare 是因为看到边缘计算浪潮刚起，加入 Kong 是因为看到微服务和云原生浪潮。判断公司的方法和投资一样——"我是投自己的青春，不是投钱"。最看重的团队特质是"往下钻一层的能力"：做 LLM infra 的能不能钻到 kernel 级别和算子优化，做网关的懂不懂网络协议栈。90% 的人"够用就行"，只有 5% 到 10% 的人有好奇心去看底下到底怎么运作。

他加入 Kong 前认识了创始人一年多，等公司从 API 聚合平台转型成网关产品的那几个月才入局。诀窍是多做功课：假设自己是 CEO 会怎么做，用脑内实验和创始人的认知做对比。主持人在旁边补了一句被反复引用的总结："如果你愿意加入这个创始人给他打工，那你就真的应该投他——打工是比给钱更重的 commitment。"

回到那个问题

戴冠兰用一句话定义 Runta："大模型相当于把电力转化成 token，智能体的工作是把 token 转化成企业真正的价值。"转化这一环发生的地方，就是执行层。

他希望在一年以后，人们讨论"Agent 需要跑在哪"时，答案像"数据放哪？数据库里"一样不言自明——Agent 跑在 Agent 执行底座上。到那时，Jeff Dean 的问题会有答案：地基变了，就在地基之上重建一套新的确定性。

而他自己对这件事的心态，藏在节目最后一段话里。被问到创业焦虑时，他说每天大概有五个好消息和五个坏消息，焦虑的根源是人们总盯着坏消息。他衡量自己状态的标准只有三个：是不是在解决一个真正让人兴奋的问题，团队配置是不是最适合做这件事，背后的支持网络是不是足够。三条都成立的时候，坏消息就只是坏消息。

  • 核心判断：执行层是 AI 落地的下一个基础设施机会——Agent 从分钟级交互变成小时/天级长跑，隔离、分叉、热迁移等老问题全部失效
  • 产业反转：Token Maximizing 到 Minimizing 只用半年；Meta/亚马逊把 token 当 KPI，Uber CEO 四月用完全年用量是转折信号
  • 竞争格局：公有云为 SaaS 设计（GPU/New Cloud 类比），模型厂商做 infra 是为了拿信号，创业公司从底层重建是历史规律
  • 安全机会：Agent 灾难性事故必然发生；模型侧无法根治（next token prediction 分不清指令和数据），管控+可审计的执行底座才是解法
  • 战术细节：服务 agentative 客户（间接服务成千上万 Agent）、token 浪费分析闭环、95% 编码交给 Agent 但架构判断仍靠人
  • 选人标准：往下钻一层的能力——5-10% 的人会去看底层怎么运作，这是招聘的第一原则
