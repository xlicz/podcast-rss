从濒临破产到 200 亿美元交易：Groq 创始人揭示了 AI 时代最被低估的能力

Jonathan Ross 十年前发明了 TPU，然后创办了一家所有人都不看好的芯片公司。三四年前，当他坚持"快速推理将是 AI 的命脉"时，连自己的员工都在离职。现在，Groq 与 Nvidia 达成的 200 亿美元合作正在重塑整个推理市场。而他说，这一切的背后是一个更根本的转变：AI 时代的赢家不是能回答问题的人，而是能提出正确问题的人。

Jonathan Ross 接到那通改变公司命运的电话时，距离钱到账只剩三周。

当时 Groq 已经走到了悬崖边缘。他刚主持了一场全员大会，放的是二战风格的战争债券海报——管那东西叫"Groq 债券"。严格来说不是债券，是用薪资换股权。80% 的员工签了协议，大约一半人把工资砍到了法定最低标准。年薪几十万美元的工程师，开始拿五六万过日子。

省出来的钱大概多撑了两个月。融资到账那天，公司账上只剩三周现金。

然后他们去找了 Jensen Huang。不是去求救，是去买 GPU——大约十万张，打算自己部署。Jensen 看了 Groq 做的东西，提了一个比卖芯片更大的想法：不如把这个方案开放给 Nvidia 所有客户。

三周。从提出想法到钱到账。

"最有意思的部分是那通电话，"Ross 回忆说，"Jensen 动作真快。当然，这样才能保持领先。"

GPU 是十八轮大卡车，LPU 是最后一公里小货车

理解这笔交易的逻辑，需要一个简单的比喻。

"如果你要为美国建一个物流网络，"Ross 说，"你可以选十八轮大卡车，或者选最后一公里配送的小货车。你选哪个？答案是两者都要。"

GPU 和 LPU 的互补性就建立在这个逻辑上。处理一个语言模型的 token 时，实际上是在做各种不同的矩阵乘法。有些更受算力限制（compute-bound），有些更受内存吞吐限制（memory-bandwidth-bound）。受算力限制的部分放在 GPU 上跑，受内存吞吐限制的放在 LPU 上跑。

"瓶颈到处都是，不存在单一策略，也不存在某种完美的架构。把这两样东西放在一起，就能在所有不同的模型上打破瓶颈。"

这个认识在 AI agent 大规模互动的时代变得尤为关键。当人类在电脑上输入指令时，可以等一两秒拿到回复。AI 不需要等——它生成 token 的速度比人快得多，思考也快得多。当一个 AI agent 调用另一个 AI agent 去完成子任务时，速度的乘数效应就爆发了。

"人类从使用 AI 中受益，AI 也一样。一个 agent 启动一个任务，去调研它要用的其他工具，然后把这个任务交给另一个 agent——你得到的是指数级的增长。"

这也解释了为什么四年前 Ross 疯狂坚持"快速推理"的时候，几乎所有人都觉得他疯了。

最孤独的信念：当所有人都在说"这不重要"

三四年前，Groq 内部阻力极大。

"很多人离开，说快速推理没有意义，不会给生态带来任何价值。"Ross 回忆当时的情形，语气平静但细节锋利。"哪怕你拿拨号和宽带这种很简单的类比来讲，也没人能联系起来。"

他们做了一个演示视频，把 LLM 的输出速度加快，展示给潜在客户看。所有人的第一反应都是同一句话："我要一个比我阅读速度还快的 LLM 干什么？"

问题出在类比上。你读网页的时候，眼睛不是逐行扫描的——你会先扫一眼，很多时候还没开始读，就有个感觉"这不是我要的"，然后开始敲你的问题，根本不会把输出的内容全读完。你需要整个页面都在那儿，立刻展示出来，让你的直觉做判断。

Ross 的理解是："这些人还没想到，你不会自己去读。而且互联网也不是这么运作的。"

真正改变局面的是一次意外。他们在网上开放了 Groq 的推理服务后，有人在 X 上发了一个视频——LLM 在 Groq 上跑，token 生成速度极快。视频爆了。用量暴涨。

"差别在于，当人们问出自己的问题，得到一个专门针对自己的答案时，那才是魔法。看别人的答案一行行冒出来，不是魔法。"

"如果你不做的跟别人不一样，你就没有优势。我们做的每件事都不受待见，每件事都被认为是坏主意。"

但 Ross 对这个经历的反思比"坚持就是胜利"深得多。他引入了一个概念，来自 Jim Collins 的书：运气回报（Return on Luck）。

Groq 其实差一点就彻底错过了 LLM 这班车。

"LLM 刚开始火的时候，GitHub CEO 打电话给我，说他们需要一大批 GPU，能用我们的 LPU 吗？我找团队说我们有机会，他们全都说不行——在这些芯片上跑不了。我说：这看起来就是最适合我们芯片跑的东西。他们说 GPU 里有很多东西我们都没有。我说：对，但那些东西对 LLM 都不重要——他们看错了地方。"

他让团队说服了他。不是一次，是两次。第三次，Ross 终于说："不行，我要自己来。"

他把整个事情过了一遍，算了算数，确定了性能指标。所有人都不同意。最后他们正好达到了那些数字。

"问题在于他们看的是所有做不成的理由，而不是能做成的原因。我们把自己说服了。如果我们当初是微软那边给 OpenAI 跑 LLM 的第一家，结果会完全不同。"

但他从这次经历里总结出了一个对他后来领导方式至关重要的观察：征求意见和表明意图，看起来只差了几个字的措辞，结果天差地别。

这来自一本名为《Turn the Ship Around》的书——一艘核潜艇的指挥官用了不到两年，把全舰队最差的战备状态带到了第一，核心手段就是把指挥模式从"命令控制"切换为"意图领导力"。

"I intend to submerge the ship to 500 feet"（我打算把潜艇下到 500 英尺）——和"征求意见式"的发问不同，这一句话激活的是完全不同的反应机制。不会引发无意义的悲观抵抗，但在真正有致命问题时，人们会站出来反对——比如"等等，舱门还开着"。

Ross 说，他在 Groq 早期的最大错误，就是反复征求别人的意见。人们给他的全是阻力。"如果我当时只是说'我打算做这件事'，反对不会消失，但参与的方式会完全不同。"

"现实商数"：你能认出当下正在玩的主导游戏吗？

Ross 在 Groq 招聘时最看重的不是智商，是他称为"现实商数"（Reality Quotient）的东西。

"有很多非常聪明的人，就算现实拍了拍他们的肩膀，他们也认不出来。他们脑子里能编出特别复杂的故事，但跟现实完全脱节。"

但现实商数的极致形态不是"认清现实"，而是"能选择当下正在玩的那个主导游戏"。

"大多数真正成功的创始人做的事就是——别人都在玩这个游戏，他们意识到，如果你玩一个更高层级的游戏，你就赢了。"

他举了一个教科书级别的例子：MySpace 关注的是注册账户数，Facebook 关注的是月活用户。月活用户才是主导游戏。你把月活做到最大，就能打败那些把注册数做到最大的人。

在 Groq 内部，他把这个主导游戏浓缩到了一个能刻在挑战币上的句子："每秒 2500 万个 token"。每个员工都有一枚这样的挑战币，上面画着一条向上的小曲线。所有人都知道这就是公司唯一的目标。芯片团队、软件团队、部署团队、供应链团队、电力团队——每个人都能把自己的工作跟那个数字连接起来。

"约束越少，解决问题的自由度就越大。你给别人的约束越少，他们就越有可能用解决方案给你惊喜。"

但这背后有一个反直觉的洞察：作为创始人，你本质上是在做全职的变革管理——而变革管理的第一原则，是让它感觉不像一场变革。

"人不喜欢变化。那些看起来喜欢变化的人和不喜欢变化的人，区别往往在于他们关注的东西不一样。对那个不介意变化的人来说，其实什么都没变——他玩的这个主导策略没变，只是在努力把每秒 token 数做到最大。当方法变了，根本的东西没变。"

他裁掉了自己的招聘方式，然后找到了真正的问题

Ross 在招聘上犯过错，而且坦白得很直接："我们招进来的很多人也造成了组织问题。"

原因在于他的默认模式是"寻找正面特质"——遇到一个聪明人，总能想出理由为什么该招他。但真正的问题不在这里。真正致命的是那些带着"负面特质"的人：正面特质是"运气回报"，对应负面就是"挥霍运气"；正面是"诗性设计"（用极少的元素表达极多的意思），负面就是"堆砌式设计"（什么功能都往里塞）。

"只要有一个人带着负面特质进来，就会把这种东西带进整个团队。"

他后来把招聘思维整个翻转了过来——从"寻找正面特质"切换为"排除负面特质"，并引入了一个让他特别看重的筛选维度：提前锁定胜利。

"人的损失偏见是天然的——亏 20% 带来的痛苦，是赚 100% 带来的快乐的六倍。但你有没有注意到，有些人亏掉 20% 会非常痛苦，他却不会因为没有投那个涨了 100% 的东西而痛苦——尽管机会成本高得多。"

Ross 观察到，顶级的创业者有一种反人性的特质：一旦听到某件事可行，他们会立刻锁定它，默认"如果我不做，就等于失去了这个东西"。在架构会议上有人说"芯片能快一倍"，大多数人听到的是"那就放到下一代"，Ross 听到的是"如果不在这一代做，芯片就只有它本可以达到的一半快"。

"所以我开始招那种会'提前锁定胜利'的人。一听到某件事可行，就立刻锁定，然后想：我不想失去这个东西。"

代码的边际成本正在趋近于零，但真正稀缺的是提问

Ross 最近发了一个引发争议的帖子，核心观点是：写代码曾经是职业壁垒，现在正在变成免费品。

"作为一个软件工程师，默认前提是写代码很贵——所以我得非常小心地决定写什么代码。除非我百分百确定某个功能该做，否则我不会动手。但现在代码的边际成本正在趋近于零。你直接把东西做出来，去体验它，然后说：根据我的体验，用另一种方式重新实现一遍。"

他把这比作文字和读写能力的历史。抄写员曾经是唯一能读写的人，他们控制着书面文字的获取。后来用字母取代了表意文字，突然间很多人都能学会阅读。再后来有了教育体系，每个人都有了这个入口，重点从"会不会写字"变成了"文字的质量"。

"我的行政助理现在就在做软件应用。我出差的时候，他会做一个小工具——点进去看天气，实时更新，从数据源拉取信息，给我所有的电话号码。这在以前对一个不懂写代码的人来说是不可能的。"

但这只是故事的一半。真正的转变更根本。

"信息时代的成功在于能回答问题，而 AI 时代的成功在于能提出正确的问题。"

这不是格言式包装。Ross 从自己的每日信息处理习惯里发现了这个规律的切实证据。他每天早上收到一封 AI 生成的"每日简报"——基于他感兴趣的东西和互动方式，做大量研究，汇总成文案推给他。一开始他读大段文字，后来他意识到：AI 已经做了那么多研究，掌握了那么多上下文，为什么不直接让它把所有东西总结成标题，然后让 Ross 自己追问后续问题？

这让他想起小时候玩的"二十问"游戏——你可以在二十个问题之内搞清楚对方脑子里在想什么。"提问能帮你把注意力收束到你真正关心的事情上。播客是静态的，你只能听。但如果你能跟信息互动，就能直接拿到你最想要的东西。"

"真正好的领导者不会自己动手干活，也不会自己给出答案。他们只是提问——消化听到的所有信息，然后问出那个别人没问、或者大家都在想但不敢问的问题。"

把这个逻辑推到极致，Ross 对教育的建议几乎是颠覆性的：别再教孩子回答问题，开始教他们提出问题。

"当你给孩子们布置作业或考试时，如果他们能在网上查到答案，或者能让 AI 来解决，那你就没有教会他们在下一个时代需要的东西。但如果你给他们一个必须自己提出问题并让 AI 来解决的问题，那你就教会了。"

他建议课程应该围绕社区真实需求重新设计——让学生改进城市审批流程，帮某个社区活动做传播，写出真正有用的应用，然后让他们自己去提问。

一个不会停止不满的人

对话接近尾声时，主持人 David Senra 问了一个很简单的问题："你今天对什么不满？"

Ross 的回答不需要任何修饰就已经足够有力：

"目前我对世界上算力不足这件事不满。AI 是革命性的——会有医学上的发现。如果因为算力不够，我们多花一年才能治愈癌症，那就是我的错。每一个死于癌症的人，每一个变老衰弱然后死去的人……也许有一天 AI 能找到延缓衰老的方法。这一切我都觉得某种程度上是我的责任。我必须拿出表现，我必须确保世界有更多算力。"

他把这种状态称为"制造不满"——不是悲观，是驱动力的持续燃料。最顶尖的企业家、运动员，任何爬到行业顶端的人，不会躺在功劳簿上赢了就睡大觉。上一个目标达成的那一刻，他们的注意力已经转向了下一个让自己不满意的缺口。

对 Jonathan Ross 来说，这个问题是算力。对他的同行们来说，各不相同——有人不满于自己的财富，有人不满于自己以前的某篇文章没写好。但驱动机制是相同的：不满，然后行动。

David Senra 在结尾时提到了宝丽来创始人 Edwin Land——乔布斯的偶像之一。Land 在发明宝丽来相机之前很久，一直在尝试减少车灯眩光。他的组织原则很简单：在办公室白板上写下"今天有三百人因此而死"。Ross 的版本是二十五个数字——"每秒 2500 万个 token"。

不是风格不同，是同一个物种的行为模式。

文末要点

  • GPU 与 LPU 不是替代关系，是十八轮卡车与最后一公里小货车的互补——不同瓶颈在不同芯片上解决，组合才能覆盖整个性能曲线。
  • 快速推理在 agent 时代是乘数效应：AI 与 AI 对话时，速度每提升一档，整个 agent 网络的吞吐和决策质量指数级增长。
  • 运气回报的关键不是比别人更幸运，是比别人更早处在能看到未来的位置上——然后在自己都说服不了别人的时候，敢于说"我要做"。
  • 征求意见和表明意图（"我打算做这件事"）的措辞差异，在实际推进中会导致完全不同的团队反应模式。前者引来悲观抵抗，后者在致命问题出现时仍能获得反馈。
  • 招聘的致命盲区不是看不出谁好，而是看不出谁带着"负面特质"——正面特质的反面版本。只要一个这样的人进来，就会污染整个团队。
  • AI 时代的核心能力不是回答问题，是提出正确问题。教育体系教孩子记住答案，下一个时代需要教他们提出 AI 无法替他们定义的问题。
  • 最优秀的创新者的燃料不是满足感，是"神圣的不满"——上一个目标达成的瞬间，注意力已经转向了下一个让自己无法忍受的缺口。
