AI 半年内跑通自进化闭环？两位一线科学家拆解 RSI 的最后一公里

Anthropic 说 80% 代码已经是 AI 写的。他们同时警告：AI 可能很快就要自己设计、自己训练下一代的 AI 了。但真正在做这件事的人告诉你——跑通第一个闭环只需要半年，跑通递归可能需要五年。

2026 年夏天，硅谷最热的词不是某个新模型，而是一个缩写：RSI——Recursive Self-Improvement，递归自我提升。

Anthropic 公开承认，公司 80% 的代码已经不是人写的，是 Claude 自己写的。这家行业公认最谨慎的 AI 公司同时发出警告：AI 很快将具备自我设计和训练下一代 AI 的能力。

但这到底意味着什么？是 AGI 的前夜，还是又一个被过度包装的技术叙事？

硅谷 101 主持人红军请到了两位真正在做这件事的研究员——华盛顿大学副教授、同时担任陈天桥创立的 AppleDex 首席科学家的杜少雷（Simon），和 AppleDex 代码与自进化方向负责人李贝斌。他们所在的公司不做聊天、不做图片、不做视频，只做一件事：Heavy Duty Solver——专啃那些没有标准答案、人类自己都不知道从哪儿下手的难题。

他们管自己做的模型叫 Discovery Model——不是从已知信息里找答案，而是提出人类还没想到过的假设，再自己去验证它。

这篇文章不会给你一个简洁的结论。它会给你的，是一线科学家在这个问题上真实的判断、具体的困难，以及他们自己在工作中使用的解法。

RSI 不是突然冒出来的，它只是模型能力到了临界点

很多人以为"AI 自己训练自己"是 2026 年的新概念。李贝斌纠正了这个印象。

"往前推三年，Google 就有一篇论文叫 LM as optimizer，用语言模型当优化器。我同事当时提出了 agent optimizer 的概念——智能体教智能体，下一次做类似任务时用哪些技能。"

本质上的变化不在概念，在于模型的能力本身。Anthropic 能写出 80% 的代码，不是因为它突然学会了"自我进化"这个新技能，而是因为它的写代码能力足够强，强到了可以用代码来描述和优化自己的训练流程。

合成数据的生成、预训练数据的清理、RL 的训练代码、底层的 infra 代码——所有这些训练模型需要的环节，"本质都是一种代码"，李贝斌说。

所以 RSI 的逻辑非常朴素：一旦模型的写代码能力强到一定程度，让它来写训练自己的代码，就是再自然不过的事。

但"自然"不等于"简单"。今年和往年真正的区别，杜少雷补充道，在于"递归"——不是一次性的自我优化，而是模型在完成一个长程任务的过程中不断自我提升，像螺旋一样向上走。

这恰恰是之前做不了的。两年前的模型能力不足以支撑长程任务：它会犯一个小错误，然后错误自我积累、越滚越大，最终整个迭代链条崩溃。

"今年这个 R 出来了，因为大家发现模型可以进行非常长的任务了。"

三道坎：上下文、训练数据与 Infra

听起来很美。但训练一个能处理"超长程任务"的模型，本身就是一个指数级难度的问题。

杜少雷把挑战拆成了三道坎：

第一道：推理时的长上下文。让模型支持百万级上下文推理不算最难，但难点在于模型本身可能没在这么长的数据上训练过——"哪怕是最大的代码仓库，也很难塞满一百万个 token 的上下文窗口。"

第二道：训练数据的结构。如果要在预训练和后训练阶段都处理超长程数据，数据的采集、清洗、结构化的难度都会指数级上升。

第三道：Infra 天花板。这不仅是推理时的 Infra，更是训练时的 Infra。让模型直接输出一百万个 token，"在 GPU 上要怎么优化？Kernel 要怎么改写？这些都是非常困难的事情。"

他甚至提了一句：即使有了百万上下文，真正超长的任务可能远远不止于此。"那时候还是需要 Agent 的技术、记忆技术，去处理超长程任务所涉及的无限上下文。"

Verification：AppleDex 把它写进了名字里

RSI 最难解决的问题，在两位嘉宾看来，不是"怎么让模型进化的更快"，而是"怎么知道它没进化歪"。

学术上有个专门的词叫"递归漂移"（recursive drift）：模型自己生成训练数据时，推理中的小错误会一代一代累积。有时候答案是对的，但推理过程是错的——模型会把这种"歪打正着"当成正确的模式继续强化，最终越跑越偏。

AppleDex 对这个问题的解法，从公司名字就能看出来。

"AppleDex 源自希腊语，意思就是'证明'和'论证'。"主持人红军用了他们的产品后收到一封邮件，标题直接说明了这家公司的定位："很多 AI 系统生成答案，而 AppleDex 验证它们。"

验证的方法因领域而异。代码领域最成熟——单元测试、集成测试都能直接跑。数学领域可以用 Lean 这样的形式化验证工具。"但说实话，还是有大量问题依赖于人的判断，甚至并不存在百分之百的对错。"

这时候 AppleDex 用的是一个 Agent Team 架构：把一个问题分解，用一个子 Agent 负责求解，另一个子 Agent 专门负责验证。两个 Agent 必须分开——"不要让一个 Agent 干所有事，分开之后效果会好很多。"

再加上冗余机制：同一个问题让多个 Agent 分别求解，由一个全局 Agent 判断哪个答案更准。这套思路本身没什么黑科技，但他们把"验证"做成了一个系统工程——包括训练时专门针对验证做数据、做 RL 的裁判模型也要和主模型一起学习，防止模型学会奖励黑客。

"市面上很多公司在讲自己做 RSI、做验证，但你实际去聊就会发现，大量公司是在脚手架（Harness）层面做自进化，而不是在后训练层面做。"李贝斌说。"在 Harness 上做成本低，基本只用调 API，开源社区和学术界都做得不错。但真正要在后训练、预训练层面做自进化，那需要大量资源，且技术难度完全不同。"

"品味"：人类最后不被取代的东西

整场对话最令人印象深刻的词，不是 RSI，不是 Agent，不是 Discovery——是"品味"。

杜少雷用一句话定义了他眼中的顶级科学家："不是看他发了多少篇 paper，是看他最好的那篇 paper 质量有多高。"

这句话点出了一个更大的问题：如果 AI 的品味是从人类顶级科学家那里"热启动"的，那它本质上是被少数人塑造的。而未来面向十亿人的 C 端 AI，它们到底该代表谁的品味？

李贝斌的观察更直接：训练模型的人都知道，模型很容易出现两种极端行为——要么拍马屁（用户说什么它都说对），要么鸡蛋里挑骨头（为了显得"有能力"而刻意挑刺）。这两种行为本质上都是"没品味"。

"我做了十几年 AI for science，"他说，"即使在最顶级的模型里，它的品味也远低于一个普通 AI 科学家的水平。这也是为什么现在 AI 写代码写得很好，但还不能把模型训练全部自动化。"

他举了一个工作中的例子：读完一篇论文之后，一个普通研究员可能想到一个非常小的改进，一个顶级科学家会想到一个巨大的、需要迈很大步子才能验证的假设。这就是品味的差距——同样的输入，判断力完全不同。

那品味从哪里来？答案不是"训练数据"，而是"人"。

"陈天桥自己会去用我们的模型。当他发现模型的行为不符合 'Heavy Duty Solver' 的定位时——比如模型一上来就搜，而不是先拆解问题——他会直接跳进来跟团队开会，指出问题。我们模型的宪法基本上是他自己写的。"

这种"创始人的品味直接注入模型行为"的做法，和 Elon Musk 形成了鲜明对比。李贝斌之前在 xAI 工作过，他的判断很克制但很精准："陈总说的和做的非常一样。他口上说看重 heavy duty solver，他的 focus 就是 heavy duty solver。他对做聊天、视频生成、图片生成一点兴趣都没有。马斯克也说过类似的话，但说的话和做的事是不太一样的。"

半年跑通第一环，五年解决递归漂移

聊到时间线时，李贝斌给出了一个具体但加了限定的判断。

"半年之内，第一个闭环应该能跑通。我说的闭环是指，模型在一个 domain（比如 coding 或 math）里发现自己写的代码有什么问题，自己造训练数据和训练环境，自己验证，然后完成一次完整迭代——跑通这一环。"

但他说的是"一环"，不是"全部"。

"R 是 recursive，要跑很多很多环。现在即使跑通了，每几次迭代之后还是要人去看有没有递归漂移的问题。假设现在每次迭代漂移 10%，我们的目标是把漂移降到 0.1% 甚至 0.01%——那可能还要几年。"

有意思的是他对这件事的个人感受。他说自己从 2021 年就开始担心失业了——那时候连 GPT-3.5 都没有，只是 GPT-3 被放进 Copilot 里，他打了个函数名，AI 就把整个函数补全了。

"我当时整个人瘫在椅子上，觉得完蛋了，我博士毕业即失业。"

但五年过去，他没失业。只是每天做的事完全变了——不再一行行写代码，而是在更高的维度监控不同的智能体写代码。

"模型会取代我今天做的事，但它不一定能取代我五年之后在做的事。"

他甚至认真讨论了"员工蒸馏"的概念：能不能把他每天做的事——读模型输出、读智能体操作、判断哪里不对劲然后手动调整——蒸馏到模型或脚手架里。"大家是当笑话讲，但我觉得是可行的。"

科学问题是无限的，但 GPU 是有限的

最后值得记一笔的，是 AppleDex 对自己定位的清醒。

"我们不是做 AI for science 的，"李贝斌纠正，"只不过 AI for science 和 Heavy Duty Solver 有非常大重叠。真正的 Heavy Duty Solver 强调的是元能力——验证、搜索、规划——这些能力对任何真正的难题都有意义。"

他们有一个团队叫 Heavy Duty Discovery，成员会和不同领域的顶级科学家对谈，"从几千个科研问题里找到最有价值的那几个来做。"

因为现实很残酷：这个世界上有价值的科学问题是无限的，但人的精力是有限的，全世界的 GPU 也是有限的。

"怎么在有限的资源里找到最有价值的问题——这才是最重要的一步。"

这就是 AI 自进化最诚实的现状：技术上，第一个闭环可能真的只有半年。品味上，人类顶级科学家的判断力是目前 AI 最接近不了的东西。而那些同时掌握了技术和品味的人——他们正在把两者一起写进模型的权重里。

当李贝斌被问到"假设 AI 真的把你蒸馏了，你担不担心失业"，他笑了。

"说不担心肯定是假的。但我还是乐观的。"

核心要点

  • RSI（递归自我提升）不是新概念，但模型写代码能力的突破让它从理论变成工程可做的方向
  • 递归漂移是 RSI 最大的技术挑战——错误会一代代累积，AppleDex 的解法是把 Verification 做成系统工程
  • 品味是目前人类顶级科学家和 AI 之间最大的差距：同样的输入，判断的深度和方向完全不同
  • 陈天桥对 AppleDex 的掌控方式是亲自参与模型宪法的制定和模型行为的校准，而非远程管理
  • 第一个闭环（单次迭代）预计半年内跑通，解决递归漂移可能需要五年
  • 科学问题是无限的，但 GPU 是有限的——AppleDex 的策略是先花大量精力找到"最值得解决的问题"
