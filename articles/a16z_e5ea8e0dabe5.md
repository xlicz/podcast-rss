把 AI 真正部署进企业：Decagon 的开源赌注与"玻璃盒"打法

90% 的工作流跑在自研开源小模型上、一个月建出 7 条客户旅程——a16z 对话 Decagon 双创始人，拆解企业 AI 从"能用"到"落地"的真实路径。

一个客户离开 Sierra 转投 Decagon 的理由很具体：在 Sierra 那边，一切都要通过 forward deployed engineer（FDE）才能动，一年只建出 3 条客户旅程，像一个黑盒；到了 Decagon，自己的非技术团队上手就能改，一个月建了 7 条。同样卖 AI 客服给大企业，交付模式的差别直接变成了迭代速度的差别。这期 a16z 播客里，主持人 Sarah Wang 和 Kimberly Tan 请来 Decagon 联合创始人 Jesse Zhang 与 Ashwin Srinivas，把企业 AI 真正的部署逻辑讲得罕见地具体：为什么 90% 的工作流迁到了开源小模型、为什么微调根本不是为了给客户做定制、forward deployed 这个时髦打法的陷阱在哪、以及 AI 到底会不会消灭工作。

## 90% 的工作流迁到开源：真正的原因是延迟，不是省钱

Decagon 创业初期用的是 OpenAI 和 Anthropic 的前沿模型——目标只是"让东西跑起来"，当然用最强的 API。转折发生在规模上来之后：客户越来越大，动辄数百万终端用户，语音 agent 上线，延迟成了硬约束。"不只是要给出好答案，还要给得足够快。"要把延迟压下去、让 agent 按自己的方式运转，唯一的路是小模型。而前沿实验室的小模型不可控，开箱即用又不够好——于是他们转向开源，这发生在一年多以前。

他们把开源小模型微调到具体任务上，结果推翻了 Twitter 上流行的那套权衡叙事。Jesse 说，人们总以为是"最聪明但贵"和"笨一点但便宜"之间的取舍，这是伪权衡："我们微调过的更小、更笨的模型，在我们要它做的那个具体任务上，表现超过大型 SOTA 模型。"于是三样东西同时拿到：任务上更强、更便宜、更快。

原因在于 agent 的工作结构。一个客服 agent 每轮对话要同时做很多事：判断用户在聊什么主题、识别来者是不是恶意行为体、决定下一步动作——每一件单独的事都不需要大模型的全部智力。大模型会做数学、会写代码，但你只需要它擅长那一件事。微调小模型，就是在这件事上做到与大模型持平甚至更好。

今天，Decagon 90% 的工作流跑在开源模型上，核心动因始终是延迟——优化语音 agent 的听感和响应速度，过去一年效果提升巨大，同时保持了准确率。剩下 10% 留给闭源前沿模型，用于新项目、新产品。模型选型其实只有三个维度：成本、智能、延迟，按需求去顶到各自的极限，能换就换。

> 我们微调过的更小、更笨的模型，在我们要它做的那个具体任务上，表现超过大型 SOTA 模型。

前沿模型仍然有位置。Decagon 最近推出的 Duet Autopilot——一个负责改进核心对话 agent 的 agent——要复盘刚发生的上百万条对话、找出趋势、生成主模型的变体再测试哪个更好。这种开放式的探索任务，还是聪明的前沿模型更合适。

## Decagon Labs 是一座"模型工厂"

为了微调开源模型，Decagon 养了一支"很贵"的研究团队。Ashwin 把 Decagon Labs 的定位说得很直白：一座模型工厂，目的是压缩"新模型发布"到"微调好的任务模型出炉"之间的时间。

原因在于模型版图变化太快。"我们不是训完一套开源模型就完事、两年后再回来。"前沿能力一变，新用例就冒出来，就有人发现"这个任务现在重复出现得很多了"，于是不断训练新模型、淘汰过时的旧模型。

企业会不会跟进自己做后训练？Jesse 的判断是会，但比人们想的慢。微调不 trivial：要拿到数据，更重要的是要有好的 evals——而 Decagon 的 evals 高度专有，用公开基准没用，必须自己生成任务专属的 benchmark。"当你的用例定型了、上了生产、规模跑起来了，agent 的形态也确定了，这时候用开源是严格更优的：延迟收益、成本收益都有。"他们当初不是为省钱去做的，省下来的成本只是副产品。

有意思的是他观察到的反向信号：眼下开源的推理份额其实在下降。原因很简单——现在冒出的都是新用例，新用例当然先用前沿模型 API，不用管基础设施；等其中一些用例跑通、企业决定全面铺开时，才有强烈动机切到开源，那会更便宜更快。企业想动，但一次只能推那么多用例，还要过模型风险治理和安全审查，惯性真实存在。"会到的，只是慢。"

## Token 成本不重要？对这个阶段的公司来说，真的不重要

"Tokenomics"是 X 上的热门话题，但 Decagon 基本不按这个框架思考。性能、延迟、准确率是驱动因素，成本是免费拿的好处——"这是少数几个三样东西不用互换的场景"。

Ashwin 补上了这背后的阶段逻辑：增长期公司当然要对成本负责，但最高优先级是增长。客户不关心你的成本，只关心 agent 表现好不好。客户眼里的产出单位是"一次对话"，不是这次对话烧了多少 token。实际上，Decagon 每次对话的 token 消耗在持续上升——为了更好的质量，他们在做更多次模型调用、更多检查、更多并行化。"等我们赢下市场了，再回头优化成本。"

Jesse 的补充更精确：tokenomics 辩论针对的是"我今天全跑在前沿模型上，要不要切开源"的公司——那种情况下算成本完全合理。一旦跨过了那道坎、知道怎么分解任务、怎么快速构建训练部署开源模型，成本压力就没那么迫切了。

## 应用层没有死，"实验室是最后的创业公司"是误读

2026 年上半年流行一个叙事：Anthropic、OpenAI 是最后的创业公司，会吃掉一切，应用只是薄薄的 UI 加一层实现。Jesse 直接反对："我不认为软件整体会以任何有意义的方式消失。"

他的类比很朴素：人类某种程度上就是 AGI，而人类一直需要软件——需要数据库存东西、需要 CRM 记录事情。就算 AGI 到来，"我们的 AGI agent 也需要一个地方存放工作、拉取信息、对事情做推理"。纯粹为人做工作而建的那类 SaaS 会受压，但应用层永远有空间。甚至长期看，应用公司可能变成"特定垂直领域的实验室"——最终产品就是那几个把具体任务做到极致的模型。

那微调是不是给单个客户做定制？这是一个普遍误解。Decagon 的微调，绝大部分是为"客服这个用例"定制，而不是为某个客户定制——他们只做这件事，跨所有客户，所以值得投入研究资源把模型调到极致。企业把自己的研究资源花在调客服行为模型上，大概率不值。

客户真正买的是模型之上的东西。"一个人打电话进来，航班取消了，要一次给三个人改签"——这是业务逻辑，AI 必须知道怎么处理，但它和模型本身无关，只能存在于应用层。这类东西包括集成、业务逻辑捕捉、测试和实验、对话回查、QA、给合规团队的监控工具。这是垂直应用该深耕的地方，也是实验室的通用 agent 覆盖不到的地方。

## Forward deployed：要么产品化，要么沦为外包

Decagon 三年前做 AI 客服时被嘲"GPT wrapper"，坚持自己下场做交付也一度显得另类。如今 "AI agent + forward deployed"成了硅谷标配话术。但 Jesse 认为这个概念被用得太松，混同了两件事：免费咨询 vs 真正做产品。

他引用 Palantir CTO Shyam 内部那句名言："forward deployed engineer 吞下痛苦，排出产品。"（eat pain and excrete product）理解是：FDE 对早期 AI 公司是必要的，因为 AI 产品的工作流没人探索过——五年前的 SaaS，用户要什么是清楚的；AI 产品没人用过，FDE 本质上是和客户一起第一次摸索工作流，"火车开到哪就把铁轨铺到哪"。但长期必须产品化："一旦你知道工作流长什么样，就该把它产品化，成为一家有技术公司规模属性的公司。做不到，那你只是在建一个光鲜的咨询公司——现代版埃森哲。"

Decagon 的 FDE 全部产出核心产品：进企业搞清楚产品今天缺什么，产出不是一次性交付物，而是"下一个要同样东西的十个客户免费拿到"的功能。Agent PM 同理，搞清楚产品怎么在企业里可部署。AOP（agent operating procedures，用纯文本写给 AI 的操作规程）本身就是产品化的产物——之前所有规程要写成代码，FDE 工作量巨大，"写成纯文本不是更高效吗"，于是做成了产品。

这引出了他们对比 Sierra 时反复强调的"玻璃盒 vs 黑盒"：交付物必须是客户自己能用、能快速迭代的产品，一切掌控在客户手里。Salesforce、Zendesk 都是横向长出来的，Decagon 也押注横向赢家——这个市场的规模收益来自产品深度，而不是垂直专属功能。

## Duet：一个 agent 把"建 agent 的活"也干了

早期搭一个客服 agent 要写 AOP、写工具和集成、建测试和模拟、上线后人工读对话。Duet 是第二个 agent——更大、更慢，但把上述所有事包了：你什么都没建，扔给它一堆对话记录和文档，说"你去搞清楚这些规程怎么写"，它自己写 AOP、自己配套写测试和模拟；上线后它监控全部对话，标出好与坏，会说"我读了这一千条对话，有个主题我们做得很差，改进方案我已经起草好了"。

这是 Jesse 眼中的 "oh shit moment"：公司刚成立时这完全不可能，是推理模型变强之后才发生的——Anthropic、OpenAI 主要为编程场景造的这些推理模型，用在 Duet 上出乎意料地好。模型显然没在"写 AOP、写测试"上训练过，却依然擅长。而 Duet 背后的每一个功能，都是 FDE 干活干出来的痛点，再被产品化：Duet 写规程省了搭建时间，于是又有了 Autopilot 来吃掉上线后的迭代时间。

## 护城河：模型之下的企业部署基础设施

直接问 Jesse：如果 AGI 真来了、模型无所不能，Decagon 凭什么十年后还有存在的权利？

他的回答绕开了"我们的数据飞轮"这类套话：短期内护城河是"让模型与企业资源协作的能力"。今天模型的能力远超企业里的实际用法——你不能把模型接上企业的一切让它自己搞定。就算假设模型完美无错，让它在企业里可部署，你需要：告诉模型什么能做什么不能做、确保它不会造成灾难性错误；让企业内部几百个各自领域里的专家协作，确认 agent 行为符合预期；测试它不越过监管红线；从数百万条对话里给其他团队提取洞察；对接一堆遗留系统。围绕模型的这些基础设施和软件，是接下来几年的关键。

"等这些被商品化——agent 能现场生成这些东西的时候？我不知道，三年后再看。"这句坦率的留白，可能是整场对话里最真实的判断。

## 卖给大企业：创始人的 80% 时间和"切块部署"

以 Decagon 的体量拿到这种大单速度是反常的——企业级合同动辄两年。Jesse 自己 80% 的时间花在销售上，核心是推速度：大银行、航司、电信，再快也是巨兽，所以要切块——不铺所有用例，先挑一两个头部用例拿下一个赢面。这种缩短周期的巧思需要创始人在场，销售团队不会替产品和端到端流程想这些配置。

他们卖的不只是产品，还有"上线路径"本身。大企业内部的问题除了"这产品行吗"，还有"我能不能让它上线"——尤其金融、强监管行业。Decagon 能从第一次会议就按颗粒度讲清楚：你的模型风险流程大概长这样、测试流程该这么做、初始灰度怎么铺、出问题怎么发现怎么修复怎么杜绝再犯。

选人上，早期销售团队一半是非传统背景转销售，一半是"常春藤运动员"。决策者押注他们时会直说："我们认为 Decagon 的创始团队会是移动最快的。"这个市场每周甚至每天都在变。

## 从客服到 AI Concierge：瓶颈是招人，不是模型

两年前 Decagon 的客户都买客服，现在定位是客户的 "AI 前台"：AI agent 就是你业务的前门，与客户的每一次互动——被动或主动——都由 AI 处理。有客户先上客服，发现"你已经很懂我们的产品和品牌了"，顺势让它接 inbound sales 做需求挖掘、按金额分派给企业销售；有客户让它做运营流程，账号一有异常就主动外呼。

底层能力的变化是"遵循指令"：几年前要给极紧的指令、死死框住；模型变强后可以给越来越宽的指导，让它像人一样补全空白。销售资格审查的对话要迂回开放式发问，这正是模型变强后才撑得起的用例。

问到当前瓶颈，答案出乎意料——是招人。"我们是 token 的贪婪消费者，但 token 账单非常低，我们缺的是人。"AI 还不能决定"该做什么、做完了没有"这种品味判断，具体执行步骤可以外包。至于"一人独角兽"论，Jesse 给了个漂亮的反例：AI 编程创业公司是这些工具最深度的用户，却在疯狂招人——因为所有人都有工具，"对手能用三分之一时间走完路线图，那就建三倍的东西"，结果所有人都在招人加出货。

## AI 会杀死岗位，但杀不死职业

客服可能是第一个被端到端自动化的工种，裁员叙事因此格外尖锐。但 Decagon 看到的实证恰恰相反，甚至像 Jevons 悖论的活案例：一家客户两年半前每月约 5 万张工单，用上 Decagon 后发现"原来我们的客户有这么多问题"，于是把支持入口放到每一个页面、放在用户最容易卡住的地方、对免费用户开放即时支持——客服成本降了，需求被释放，做更多而不是裁更多。

Jesse 的措辞很克制："AI 会杀死岗位（jobs），但杀不死职业（careers）。"那些被自动化的活本来就不该由人做——高频、单调、点这里点那里报答案。但让客户更满意、被更好地照顾，这件事接近无限。BPO 的情况则依客户而异：有人大幅减少外包，有人业务增长太快、只求运营不扩张，有人把人转去做更多创收的事——先从降本用例开始，成熟后创收用例也会走进这个对话界面。

Ashwin 自己的实践给了结尾一个轻盈的注脚：他给自己造了个持续收集业务上下文的 agent——"像在我身后看着"，记下招了谁、要招谁、在推什么单、卡在哪。之后问它"这个候选人怎么样"，它会推理："你们之前两个很像的候选人缺这些技能，这个人又一样，需要互补型的。"而 Jesse 拿 Zuckerberg 公开的那条 "disagree with me" prompt 去给妻子用，一天后妻子抱怨："Claude 一整天对我好凶，我只好关掉了。"

如果 AGI 让"职业"都变得可疑，那 Ashwin 的这个 agent 也许就是答案的样子：把上下文交给机器，把判断留给自己。而 Jesse 相信 AGI 之后依然有职业——"大多数工作本来就是人给自己发明的，AGI 会改变工作内容，但你还是会为其他人做事。"

## 文末要点

- 选模型看成本、智能、延迟三个维度；微调小模型在单一任务上可超越 SOTA 大模型，"省钱的聪明模型 vs 昂贵的聪明模型"是伪权衡。
- 用例定型、上生产之后，切开源是严格更优（延迟+成本），但企业迁移比想象中慢：自有 evals、模型风险治理和组织惯性都是真门槛。
- AI 应用的真正资产在模型之上：业务逻辑（AOP）、集成、测试、合规监控与洞察提取——这是应用层的护城河，也是"实验室吃掉一切"叙事的盲区。
- Forward deployed 的唯一合法目的是产品化（"eat pain, excrete product"），否则就是咨询公司；玻璃盒（客户自己能迭代）会赢黑盒（一切经由 FDE）。
- Token 成本在增长期不是核心矛盾——客户买的是"一次对话"的产出质量；每对话 token 消耗上升是主动的质量投入。
- AI 释放的需求可能大于消灭的岗位（5 万工单案例）：它杀死单调的岗位，但让"照顾好客户"这件事变得无限可做。
