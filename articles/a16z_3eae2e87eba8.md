# 开放权重模型最大的一周：权力正在换手

**Kimi K3 与 Qwen 新版本接连落地，美国前沿实验室第一次同时面对定价与守门两重压力——Sriram Krishnan 谈这背后的算力、安全与政策连锁反应。**

---

一个在美国做安全的人，最近改用中国的开放权重模型给自己的代码找漏洞。原因不是它更强，而是美国的模型会拒绝他。刚卸任的白宫 AI 高级政策顾问 Sriram Krishnan 把这种场面称为「一个很奇怪的位置」：美国最需要加固自家软件的时刻，它的前沿模型却在把防御者推开。

过去一周让这种别扭有了更大的背景。Grok 4.5、Meta 与 Thinking Machines 的新模型、Kimi K3、Qwen 新版本先后发布，Krishnan 在 X 上写下「Kimi K3 是一个重要时刻，对整个行业有多重含义」。他刚结束在美国政府担任 AI 高级政策顾问的任期，此前是 a16z 的普通合伙人，也在微软、Meta、Snap、Twitter 担任过高级职位。回到 a16z 的 New Economies 栏目，他与 Theo Jaffee、Sofia Puccini 谈的正是这件事：开放权重模型不再只是追赶者，它开始同时改写三样东西——前沿实验室的定价能力、产品护城河的位置，以及华盛顿「要不要限制中国开源模型」的权衡。

## 4 到 5 个月前，领先的还只有 Opus 和 GPT

Krishnan 提醒听众多看几步。4 到 5 个月前，能被称为领先的只有 Opus 4.6、4.7 和 GPT-5.4、5.5 那一档模型，行业里流行的叙事是：前沿实验室会沿着自我改进的曲线，把所有人越甩越远。

几周之内，这个共识被撕开了。Elon Musk 与 xAI（SpaceX 体系）拿出 Grok 4.5，他本人在用，评价是「极好的模型」；Meta 方面由 Alex Wang 带队发布了新模型；Mira Murati 的 Thinking Machines 拿出了首个模型，在多个 benchmark 上接近最优。最重要的新闻发生在最后几天——Moonshot 的 Kimi K3 上线，紧接着，就在过去 24 小时里，Qwen 的新版本落地。

Krishnan 说自己做的正是 token 消费的生意，所以对供给端格外敏感：「这是一段很好的时光。」选择变多本身就是价值：你可以把惯用的 harness 或 agent 指向不同的模型，而不必被单一供应商锁住。

## 选择一多，价格就先松动

他的第一个推论很直接：当获取「智能 token」的渠道变多，前沿模型必然承压。要么降价，要么想办法匹配价格——两条路都会侵蚀毛利。受益者是链条上更靠下的玩家：像 Baseten、Fireworks 这样的 neo cloud，或者任何手里有一批 Blackwell、又能拿到电的人。

但比「谁更便宜」更关键的是任务分层。他给了一个日常化的判断：有些 agent 需要绝对前沿的智能，比如处理复杂推理的任务；而更多 agent——帮他查邮件、快速扫一遍日历——根本不需要前沿 token，「前沿减一档」或者开放权重模型就够用。当大量真实工作可以下沉到便宜一档的模型上，前沿实验室的定价权就不再完整。

有个细节可以佐证压力已经传导到产品节奏上：Anthropic 已经延长了旗下一款前沿模型的可用期限——按原计划，它大约在一周前就该停止提供，如今被延期了。Krishnan 强调自己没有内部消息，不知道这背后是否就是竞争压力，但他预测还会有更多延期，否则市场上就摆着一款能力「非常接近前沿」的开放模型，等着接走用户。

## 护城河在智能，还是在产品

由此引出他更在意的一个问题：

> 如果前沿实验室的护城河不在智能上，那它在哪里？是智能，还是 harness？

他判断，真正稀缺的东西可能正在位移。智能本身——至少在真正前沿之下的那几个层级——正在变成一种更接近大宗商品的东西。于是前沿实验室的精力会更多投向产品层：让工具变得黏、变得难以替换。他以 Anthropic 的产品线为例，认为 Claude Code 这类工具非常好用，接下来会看到更多让它们留在用户工作流里的努力。

这条判断反过来也解释了为什么「开放权重会不会毁掉前沿实验室」是个问偏了的问题：被商品化的从来不是最顶上那一小截能力，而是它下面那一大片。

## 「用美国模型查自己代码的漏洞，比用中国模型更难」

访谈中最刺人的一段，来自一个私人观察。Krishnan 提到一位朋友最近开始用 Kimi K3 做安全研究，而不是用某款美国前沿模型——因为一用后者，他就会不断撞上拒绝与安全护栏。他的评价是：这是一个「非常奇怪的位置」。

同一天还有一条报道在流传：Hugging Face 发现有人（几乎可以确定是一个 AI/LLM agent）在多个位置对它发起高强度冲击，试图找到入侵路径。攻击方已经在用 agent 规模化作业，而防御方却在被自己的模型劝退。

> 我不喜欢我们处在这样一个位置：用一款美国模型去检查自己代码里的漏洞，比用一款中国模型更难。

他的结论不是放松安全，而是把顺序摆对：必须确保美国及其盟友的防御方拿到最好的模型，同时让软件本身更安全。他给出的解法带着工程师的直觉——很多时候，对付网络安全威胁的办法，恰恰是投入更多 AI 去扫自己的代码库，把地基加固好。

## 华盛顿的两难：要不要限制中国开源模型

就在这次对谈当天，Axios 报道称特朗普政府正在考虑限制中国的开源模型，理由有两个版本：一是「来自中国」，涉及国家安全；二是它们已在 agentic coding 上逼近前沿能力，可能构成网络安全问题。

Krishnan 先声明自己「不再靠美国纳税人的钱生活」，没有内部消息，随后把判断拆成几层。

起点并不反开源。回到一年半前，特朗普政府的 AI 行动计划出来时，第一页就在强调开源的重要性。

他真正在意的不是「开源与否」，而是领先者是谁：「我不认为领先的开放权重模型不是美国的，是一件好事」，「我更希望领先的模型是美国的」。他承认 Moonshot、DeepSeek、Qwen 做出了很好的创新，同时认真数了西方手里的牌——Google 的 Gemma、NVIDIA 的 Nemotron、Thinking Machines，以及 Reflection 这样的新公司。他的判断是它们会越来越好，但此刻领先的确实是中国模型。

他个人的世界观也偏开源：开源是他进入计算机世界的入口，他一直认同 Linus Torvalds 那条被称作 Linus 定律的说法——只要有足够多的眼睛盯着，所有 bug 都是浅的。权重一旦开放、可以从 Hugging Face 下载，全世界都能把它拆开、检查、微调、改写；闭源模型做不到这一点。在他看来，开放权重带来的是一种性质完全不同的安全增量。

于是矛盾就摆在政策制定者面前：把开源模型挡在外面，和让防御方用上最强工具，方向刚好相反。

## 蒸馏争论：三层讨论，一个不对称

X 上关于「蒸馏」的争论很热，Krishnan 把它拆成了三层。

第一层是事实前提：今天所有的模型，都是站在人类知识之上蒸馏出来的。最早的 GPT、最早的 Claude，都得爬互联网、爬博客和推文，把人类的知识吞进去做启动。蒸馏从来就是训练的一部分，躲不开。

第二层是他自己的尴尬经验：现在写一条推文，他会害怕不小心用了多个连字符，或者写了什么让 AI 文本检测工具 Pangram 判定「这是 AI 生成的」。他最近真的把自己亲手写的一条推文丢进 Pangram 里检测，明知每一个 token 都是人写的。这种紧张感的来源是 AI slop——互联网这两年的增量里，有相当一部分是模型生成的，你我每天都能读到那种「里面一定有些 token 是 AI 写的」的内容，而这些内容又回流进了下一轮训练。所以「模型学模型」这件事，已经从边缘操作变成了行业常态。

第三层才是真正的争议：工业化的、上规模的蒸馏。假账号、把 Claude 订阅转售给别人、通过各种方式转接请求——这些做法违反服务条款，性质完全不同。他认为实验室（在政府配合下）应该把 KYC、IP 地址核验这类手段做到位，阻止对推理轨迹的「重工业式提取」。

但他指出一个更根本的问题，并把功劳给了一位红杉（Sequoia）投资人此前的帖子和 Stratechery 的 Ben Thompson（同一天提出类似想法）：今天的规则是不对称的。一些其他国家的模型可以拿美国模型来训练，而美国的开放权重模型却搞不清自己能不能蒸馏美国模型——「一个有真实产品的硅谷创业公司，不知道法律状况是什么」。更微妙的是，他说你今天随便打开一个美国开源模型，它多半都在把中国模型当作 teacher，或者把中国模型的输出放进微调流程。出路是把「蒸馏可以做到什么程度」明确下来并加以保护，让美国公司和别国公司站在同一条起跑线上。

## 递归自我改进：一个被问偏了的问题

主持人抛出的问题是当下最热的那一类：Anthropic 写过相关文章，OpenAI 也谈过路径——先造一个自动化的研究实习生，再走向自动化 AI 研究。如果这真的发生，能力进步的速度会非常快。政府该有什么政策？

Krishnan 的回答先是降温：RSI（递归自我改进）是否真实、「你站在指数曲线的什么位置」，本身就是一个争论极大的话题。一派认为几年内就会出现自动化的 AI 研究员；另一派认为有些基础性改进根本啃不动，模型训练模型确实会带来提升，但曲线会平缓得多，不会是陡峭的拐点。

接着他说出自己的取径：这个问题常常被问得太理论化。他自己在政府期间的关注点是——先让生态繁荣，让人竞争着做产品、让创新尽可能快地推进；然后在可信风险真正出现时，精确地去解决那一个风险。他举的例子很具体：当模型已经能针对最新的固件或操作系统生成 exploit 时，这才是一个必须动手的题目。

由此他把大问题拆成三问：一，怎么保证市场上有足够多的竞争性选择；二，什么是我们确知可信的威胁——他点名网络安全与生物领域；三，怎么具体应对。对第三问，他的答案仍然是「用 AI 打 AI」。

## 开放权重会吓退资本开支吗

主持人转述了 Dean Ball 提出的一个担忧：开放权重模型会抑制资本开支，摧毁前沿实验室靠能力领先变现的可能。那么怎样才能既保持开源生态健康，又让前沿实验室继续做它们最擅长的事？

Krishnan 的答案是回到生意第一性原理：

> 如果你提供的是有价值的产品，资本主义会自己找到让供应链为你服务的方式。

他的推理是：一个真正有价值的开放权重模型，会牵动它下面的每一层——neo cloud、数据中心、芯片供应商，乃至给数据中心提供燃气轮机和消防系统的公司——都调整自己去交付价值。他举了两个具体场景：开放权重厂商可能去服务一家银行，因为这家银行不想和前沿模型提供商打交道，它想要一个能跑在自己机房里、数据不外流的东西；Thinking Machines 则在用客户不愿外泄的内部数据做定制微调。

他还给自己的判断补了证据：去看推理云的表现，去看产业链其他环节的增长——「相当强劲，甚至可以说壮观」，而且他认为这种增长会继续。

## 尾声：从追赶者到定价者

把这一周放进更长的时间轴，变化其实不是「又多了几个模型」。开放权重模型此前一直是追赶者的角色，靠性价比和可自托管争取那些对前沿能力不敏感的场景；而这一周之后，它的位置变了：它开始对前沿实验室的定价形成真实约束，同时在美国最不想失去的战场上——安全与政策——制造了新的两难。

真正稀缺的东西因此也被重新分配。不是最强的那一个模型，而是三件事：把「有得选」变成可用产品的工程能力，把电力和芯片变成交付能力的供应链位置，以及把政策不确定性变成确定规则的制度能力。Krishnan 那句「提供有价值的产品，资本主义会自己安排其余的」，反过来读同样成立：当「选择」本身已经存在，能被守住的护城河只剩下产品、渠道与规则。

至于他自己，离开政府后他会做更多直播连线，开始 stream，对具体去向则「令人讨厌地含糊其辞」。他只讲清了一件事：确保美国和盟友能大规模获得智能——不管它来自前沿实验室还是开放权重模型——并让政府与企业学会协作，这是他在那 18、19 个月里最想做成的事，也是接下来要继续做的事。其余的，他说，就是写一些很带劲的帖子，偶尔跳进直播间。

**文末要点**

- 一周之内，Grok 4.5、Meta 与 Thinking Machines 的新模型、Kimi K3、Qwen 新版本接连发布；Krishnan 的判断是，开放权重模型首次对前沿实验室形成真实的定价压力，而不只是「追赶」。
- 压力的来源不是参数差距，而是任务分层：查邮件、扫日历这类 agent 不需要前沿 token，前沿减一档或开放权重足以胜任，这会持续压缩前沿模型的毛利空间。
- 前沿实验室的护城河可能从智能挪向产品：Claude Code 这类工具会得到更多投入，因为「前沿之下的智能」正在商品化。
- 一个反直觉的安全后果：美国前沿模型在网络安全用途上的拒绝与护栏，正在把做防御的人推向中国的开放权重模型；Hugging Face 当天披露的 AI agent 攻击事件让这件事更刺眼。
- 华盛顿考虑限制中国开源模型，与特朗普政府 AI 行动计划第一页对开源的强调存在张力；Krishnan 的立场是「我更希望领先的模型是美国的」，而非封禁开源。
- 蒸馏争议的核心不是能不能学别人的输出，而是规则不对称：别国模型可以拿美国模型当 teacher，美国开放权重模型却不知道自己能否合法蒸馏美国模型，需要把规则明确并加以保护。
- 他认为 RSI 之争过于理论化，更可行的思路是三点：保证竞争性选择、锁定确知可信的风险（网络与生物）、并用 AI 去防御 AI。
